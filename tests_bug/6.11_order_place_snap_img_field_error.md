# Bug Report: 提交订单接口生成订单快照时访问不存在的商品主图字段

**Bug ID**: BUG-ORDER-PLACE-001  
**标题**: `POST /v1/order` 下单时访问不存在的 `main_img_url` 属性导致服务器端异常  
**模块**: 订单系统 / 提交订单 / 订单快照  
**严重级别**: 高  
**优先级**: P0  
**状态**: 已修复  
**发现日期**: 2026-06-11  
**提交人**: 测试团队 1号

---

## 一、问题概述

调用提交订单接口 `POST /v1/order` 时，即使请求 Body 格式正确、商品存在、用户也已配置收货地址，接口仍返回 `服务器端异常`。

该问题会导致用户无法正常提交订单，直接阻断下单主流程。经定位，问题发生在订单服务生成订单快照时，代码访问了商品对象中不存在的 `main_img_url` 属性，导致运行时异常。

---

## 七、根因分析

### 1. 现象分析

该问题不是请求参数格式错误导致的，因为请求 Body 符合 `OrderPlaceValidator` 要求：

```json
{
  "products": [
    {
      "count": 1,
      "product_id": 1
    }
  ]
}
```

该问题也不是用户缺少收货地址导致的，因为当前用户已存在地址记录。

异常发生在订单服务生成订单快照阶段，即库存校验通过后，创建订单前。

### 2. 关键代码 / 关键逻辑

提交订单接口调用链：

```text
POST /v1/order
  -> OrderService().palce(uid=g.user.id, o_products=products)
  -> __get_order_status()
  -> __snap_order(status)
  -> __create_order(order_snap)
```

问题代码位于 `app/service/order.py` 的订单快照生成逻辑中。修复前代码访问了商品对象的 `main_img_url` 属性：

```python
snap['snap_img'] = self.s_products[0]['main_img_url']
```

但 `Product` 模型中真实字段定义为 `_main_img_url`，并通过 `main_image` 属性对外提供图片地址：

```python
_main_img_url = Column('main_img_url', String(255), comment='主图id，这是一个反范式设计，有一定的冗余')

@property
def main_image(self):
    return self.get_url(self._main_img_url)
```

`Product.keys()` 中也隐藏了 `_main_img_url`，对外追加的是 `main_image`：

```python
def keys(self):
    self.hide('_main_img_url', '_from').append('main_image', 'images')
    return self.fields
```

因此，订单服务访问 `main_img_url` 会触发属性不存在异常，最终被全局异常处理包装为 `服务器端异常`。

### 3. 根因结论

问题根因是订单快照逻辑使用了错误的商品主图字段名，访问了 `Product` 对象不存在的 `main_img_url` 属性。当前模型实际应通过 `Product.main_image` 获取主图地址。

---

## 八、修复方案

### 当前采取的修复策略

已将订单快照中商品主图取值方式从不存在的 `main_img_url` 改为 `Product.main_image`。

修复前：

```python
snap['snap_img'] = self.s_products[0]['main_img_url']
```

修复后：

```python
snap['snap_img'] = self.s_products[0].main_image
```

### 后续推荐优化方向
- 统一商品模型字段命名，避免数据库字段、模型私有字段、序列化字段混用。
- 为订单快照生成逻辑增加单元测试。
- 为 `POST /v1/order` 增加接口级回归测试，校验返回订单号和订单 ID。
- 对全局 `999 服务器端异常` 增加日志输出和错误追踪，便于快速定位真实异常。

---

## 九、修复结果

当前问题已修复。

修复后使用相同请求再次调用 `POST /v1/order`，接口已可成功创建订单，不再返回 `服务器端异常`。

验证请求：

```json
{
  "products": [
    {
      "count": 1,
      "product_id": 1
    }
  ]
}
```

验证结果：订单提交成功，接口返回订单信息。

## 十、建议

1. 将 `TC-ORDER-001` 加入核心冒烟测试，确保提交订单链路持续可用。  
2. 在订单创建成功后，测试应校验 `order` 和 `order_product` 表是否实际新增记录。  
3. 对订单快照字段进行专项校验，包括 `snap_img`、`snap_name`、`snap_items`、`snap_address`。  
4. 对模型序列化字段和业务服务字段引用进行静态排查，避免再次访问不存在的属性。  
5. 对 500/999 类异常补充服务端 traceback 日志，避免接口只返回通用错误导致定位困难。
