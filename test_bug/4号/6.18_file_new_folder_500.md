**模块**: 文件管理 / 文件夹操作  
**严重级别**: 高  
**优先级**: P0  
**状态**: ⚠️ 部分修复 — 500 已消除，但发现新问题

**更新日期**: 2026-06-19  
**提交人**: 测试团队 4号

> ⚠️ 注：500 错误已修复（DB 层 `UrlFromEnum.LOCAL.value`），但 2026-06-19 测试中发现 `POST /cms/file/new` 存在新问题：返回 `error_code: 0` 但文件夹未实际创建。详见 [6.19_file_new_folder_returns_success_but_not_created.md](./6.19_file_new_folder_returns_success_but_not_created.md)

## 一、问题概述

TC-FILE-013（新建文件夹）和 TC-FILE-027/028（文件夹上传与移动）中调用 `POST /cms/file/new` 创建文件夹时，接口返回 500 服务器端异常：

```json
{"error_code": 999, "msg": "服务器端异常", "request_url": "POST /cms/file/new"}
```

---

## 二、测试结果

| 用例 | 操作 | 实际 | 期望 |
|------|------|------|------|
| TC-FILE-013 | 新建文件夹 | 500 | 200 |
| TC-FILE-027 | 文件夹上传与移动（第1步） | 500 | 200 |

---

## 三、根因分析（已确认 ✅）

**与 BUG-FILE-UPLOAD-500-001 完全同根因**。

新建文件夹也是通过 `File.create()` 写入 `file` 表，触发同一个 `DataError`：

```
sqlalchemy.exc.DataError: (pymysql.err.DataError) (1366, 
"Incorrect integer value: 'UrlFromEnum.LOCAL' for column 'from' at row 1")
```

根因代码：`app/models/file.py:22`
```python
_from = Column('from', SmallInteger, default=UrlFromEnum.LOCAL, ...)  # ❌ 应为 .value
```

---

## 四、修复方案

修复 `app/models/file.py` 第22行（已于 2026-06-19 完成）：

```python
# 修改后
_from = Column('from', SmallInteger, default=UrlFromEnum.LOCAL.value, ...)
```

---

## 五、修复结果

✅ **已修复，与 BUG-FILE-UPLOAD-500-001 一起修复**

需重启服务器后重新测试验证 TC-FILE-013、TC-FILE-027、TC-FILE-028。
