# Bug Report: 禁止上传文件类型测试始终生成 .exe 文件，无法验证其他禁止类型

**Bug ID**: BUG-FILE-FORBIDDEN-TYPE-001  
**标题**: `test_upload_failure` 中所有 `use_forbidden_file` 用例始终生成 `.exe` 文件，导致 TC-FILE-008 无法真正验证 `.sh` 类型的拦截  
**模块**: 文件管理 / 上传校验 / 自动化测试  
**严重级别**: 低  
**优先级**: P2  
**状态**: 已定位  
**发现日期**: 2026-06-18  
**提交人**: 测试团队 4号

---

## 一、问题概述

4号文件上传测试中，`test_upload_failure` 函数通过 `use_forbidden_file: true` 标记来控制生成禁止上传的文件类型。YAML 中 TC-FILE-007 期望测试 `.exe` 被拒绝，TC-FILE-008 期望测试 `.sh` 被拒绝，但 Python 代码中的 `_make_forbidden_file()` 函数硬编码只生成 `.exe` 文件，导致两个用例实际测试的是同一个文件类型，TC-FILE-008 无法达成其设计目的。

---

## 二、影响范围

### 受影响功能
- 文件上传禁止类型校验
- 自动化测试覆盖完整性
- 不同禁止文件类型的区分验证

### 受影响接口
- `POST /v1/file`（文件上传）

### 业务影响
- TC-FILE-008（`.sh` 文件拒绝）从未被真正验证
- 如果服务端只拦截了 `.exe` 而未拦截 `.sh`，此缺陷不会被发现
- 测试覆盖存在盲区，伪通过风险

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地开发环境
- 服务地址：`http://127.0.0.1:5000`
- 测试文件：`tests/api/4号/test_file_cases.py`
- YAML用例：`tests/cases/4号/file_cases.yaml`

## 四、复现步骤

### 步骤 1：查看 YAML 用例定义

`file_cases.yaml` 中：

```yaml
- id: TC-FILE-007
  tag: upload_failure
  desc: 上传不支持的文件类型（exe）
  params:
    use_forbidden_file: true
  expected:
    status_code: 400

- id: TC-FILE-008
  tag: upload_failure
  desc: 上传不支持的文件类型（sh）
  params:
    use_forbidden_file: true
  expected:
    status_code: 400
```

### 步骤 2：查看 `_make_forbidden_file()` 实现

```python
def _make_forbidden_file():
    import tempfile, os
    tmp = tempfile.NamedTemporaryFile(suffix=".exe", delete=False)
    tmp.write(b"MZ\x90\x00")  # DOS executable header
    tmp.close()
    return tmp.name
```

### 步骤 3：观察

TC-FILE-007 和 TC-FILE-008 调用 `_make_forbidden_file()` 时，都会生成 `.exe` 后缀文件。TC-FILE-008 实际测试的不是 `.sh` 文件。

---

## 五、实际结果

TC-FILE-007 和 TC-FILE-008 均使用 `.exe` 文件进行测试，`.sh` 文件类型从未被验证。

---

## 六、预期结果

TC-FILE-008 应使用 `.sh` 文件进行上传测试，验证服务端对 shell 脚本文件类型的拦截能力。

---

## 七、根因分析

### 1. 现象分析

`_make_forbidden_file()` 函数未接收任何参数来指定文件类型，后缀 `.exe` 是硬编码的。

### 2. 关键代码

```python
# tests/api/4号/test_file_cases.py
def _make_forbidden_file():
    tmp = tempfile.NamedTemporaryFile(suffix=".exe", delete=False)
    ...
```

### 3. 根因结论

`_make_forbidden_file()` 缺少文件类型参数，无法根据用例需求生成不同后缀的禁止文件。

---

## 八、修复方案

### 推荐修复

将 `_make_forbidden_file()` 改为接受 `suffix` 参数：

```python
def _make_forbidden_file(suffix=".exe"):
    tmp = tempfile.NamedTemporaryFile(suffix=suffix, delete=False)
    tmp.write(b"MZ\x90\x00")
    tmp.close()
    return tmp.name
```

并在 YAML 中为 TC-FILE-008 增加 `forbidden_suffix: ".sh"` 字段，由 `_get_upload_file_for_case()` 读取并传入。

### 后续推荐
- 为每种禁止上传的文件类型（`.exe`, `.sh`, `.bat`, `.dll` 等）补充独立用例
- 确保 `_get_upload_file_for_case()` 能够根据用例参数区分生成不同禁止文件
