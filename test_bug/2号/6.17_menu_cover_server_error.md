# Bug Report: Menu 覆盖接口返回服务器异常

**Bug ID**: BUG-MENU-COVER-001  
**标题**: PUT `/cms/menu` 覆盖权限组菜单时返回 500 服务器异常  
**模块**: 菜单管理  
**严重级别**: 高  
**优先级**: P0  
**状态**: 已定位  
**发现日期**: 2026-06-17  
**提交人**: 测试团队 2号

---

## 一、问题概述

调用 `PUT /cms/menu` 为权限组覆盖菜单列表时，接口返回 HTTP 500（`error_code: 999`，服务器异常）。传入合法路由 ID（如 `[1,2,3,10]`）均无法成功。

该接口是菜单分配核心功能——无法覆盖意味着无法为不同权限组配置差异化菜单，RBAC 体系不完整。

---

## 二、影响范围

### 受影响功能
- 菜单覆盖（`PUT /cms/menu`）
- RBAC 权限菜单差异化配置
- 菜单覆盖后一致性验证

### 受影响接口
- `PUT /cms/menu`

### 业务影响
- 无法修改任何权限组的菜单配置
- 前端菜单管理页面不可用
- 权限组无法获得定制化菜单

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地开发环境
- 服务地址：`http://127.0.0.1:5000`
- 数据库：MySQL 8.4.9
- 测试数据：路由节点 id=1~10，权限组 id=2
- 测试接口：`PUT /cms/menu`

## 六、预期结果

## 七、根因分析

### 1. 现象分析
- 接口无鉴权装饰器限制（仅需登录），认证通过后进入业务逻辑，问题不在鉴权层。
- `MenuDao.cover_menus()` 内部调用 `RouteTree.generate_by_dir()` 解析传入的 `routes` 数组。
- **`generate_by_dir()` 期望接收的格式与传入的 `[1,2,3,10]` 简单数组不匹配**——该方法期望每个元素是包含 `id` 字段的对象，而传入的是纯数字。

### 2. 关键代码
- [app/api/cms/menu.py:30-33](app/api/cms/menu.py#L30-L33)：从 `request.json` 提取 `group_id` 和 `routes`
- [app/dao/menu.py:56-67](app/dao/menu.py#L56-L67)：`cover_menus()` 先删除旧菜单，再调用 `generate_by_dir({'id': 0, 'children': routes})`
- `generate_by_dir()` 遍历 `children` 时对每个元素做 `route['id']` 访问，对整数 `1` 执行此操作抛出 TypeError

### 3. 根因结论

**传入的 `routes` 简单整数数组（`[1,2,3,10]`）与 `OrderTree.generate_by_dir()` 期望的对象数组格式不兼容。** `generate_by_dir({'id': 0, 'children': [1,2,3,10]})` 遍历 children 时，`OrderTree` 覆写的方法执行 `child_node_dir['order'] = order`，对整数 `1` 执行下标赋值触发 `TypeError: 'int' object does not support item assignment`，未捕获后表现为 HTTP 500。

**关键代码定位**：
- `app/libs/utils.py:104-117`：`OrderTree.generate_by_dir()` 中 `child_node_dir['order'] = order` —— 当 child_node_dir 是整数时 TypeError
- `app/dao/menu.py:56-67`：`cover_menus()` 将 requests 数组直接传入 `generate_by_dir({'id':0, 'children': routes})`

---

## 八、修复方案

### 当前采取的修复策略
- **方案 1**：在 `cover_menus()` 中判断 `routes[0]` 类型，若是 `int` 则转换为 `[{"id": rid} for rid in routes]`
- **方案 2**：前端/Swagger 传参时直接传对象数组格式

### 后续推荐优化方向
- API 层增加参数校验（Validator），确保 `routes` 格式符合预期再进入 DAO
- DAO 层增加异常捕获和日志记录
- `PUT /cms/menu` 应增加 `@auth.group_required` 鉴权
