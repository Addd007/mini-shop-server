# Bug Report: 登录日志列表时间参数校验缺陷

**Bug ID**: BUG-LOGIN-LOG-001  
**标题**: `GET /cms/log/login/list` 在非法时间参数下仍返回 200 和空列表  
**模块**: 登录日志 / 日志查询  
**严重级别**: 中高  
**优先级**: P1  
**状态**: 已定位  
**发现日期**: 2026-06-14  
**提交人**: 1号

---

## 一、问题概述

调用登录日志列表接口 `GET /cms/log/login/list` 时，如果传入非法的 `start` / `end` 时间参数，接口没有按预期返回参数错误，而是直接返回 `200` 和空列表。

例如，以下请求都出现了异常表现：

- `start=2026-01-01 00:00:00&end=asdf`
- `start=2026-01-01 00:00:00&end=456789`
- `start=2026-13-40`

这会导致调用方无法区分“确实没有数据”和“查询条件非法”，影响日志筛选和问题排查。

---

## 二、影响范围

### 受影响功能
- 登录日志列表查询
- 登录日志时间范围筛选
- 登录日志参数校验

### 受影响接口 / 页面
- `GET /cms/log/login/list`

### 业务影响
- 非法查询条件被静默接受，导致排查困难
- 前端会误以为是“空结果”，而不是“参数错误”
- 日志筛选准确性下降，影响运维和审计场景

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地开发
- 服务地址：`http://127.0.0.1:5000`
- 数据库：本地测试库
- 测试数据：`fake.py` 初始化数据
- 测试接口 / 页面：`GET /cms/log/login/list`

## 四、复现步骤

### 步骤 1：启动服务
使用开发环境启动后端服务。

### 步骤 2：请求登录日志列表接口
发送如下请求：

```text
GET /cms/log/login/list?page=1&size=20&start=2026-01-01%2000:00:00&end=asdf
GET /cms/log/login/list?page=1&size=20&start=2026-01-01%2000:00:00&end=456789
GET /cms/log/login/list?page=1&size=20&start=2026-13-40
```

### 步骤 3：观察返回结果
查看接口返回状态码和响应内容。

### 步骤 4：对比预期行为
确认是否应返回参数错误而不是空列表。

---

## 五、实际结果

接口实际返回：

- HTTP 状态码：`200`
- 响应内容：空列表或正常分页结构

示例：

```json
{
  "error_code": 0,
  "msg": "成功",
  "data": {
    "total": 0,
    "current_page": 1,
    "items": []
  }
}
```

部分情况下也可能返回 `500`，但当前主要问题是非法参数未被正确拦截，仍返回成功响应。

---

## 六、预期结果

当 `start` / `end` 传入非法时间格式时，接口应先进行严格校验，并返回参数错误：

- 非法日期格式应返回 `400`
- 非法时间戳格式应返回 `400`
- 不应进入正常查询流程
- 不应返回 `200` 和空列表掩盖问题

---

## 七、根因分析

### 1. 现象分析

虽然接口存在时间参数处理逻辑，但在实际请求链路中，非法 `start` / `end` 并没有被可靠拦截。

### 2. 关键代码 / 关键逻辑

- `app/api/cms/login_log.py`
- `app/core/utils.py`
- `app/validators/forms.py`
- `LoginLogDao.get_log_list(...)`

### 3. 根因结论

问题根因是登录日志列表接口的时间参数校验链路不稳定，非法值没有在接口入口被强制拦截，导致错误参数继续进入查询逻辑，最终返回了成功响应。

---

## 八、修复方案

### 当前采取的修复策略
- 在登录日志列表接口入口处对 `start` / `end` 做显式校验
- 支持合法时间戳与日期格式
- 非法输入直接抛出参数错误

### 后续推荐优化方向
- 将时间参数校验统一抽象到公共校验层
- 为所有日志查询接口统一时间格式规范
- 补充时间戳 / 日期 / 非法格式的自动化回归用例

---

## 九、修复结果

当前已开始针对该问题进行修复，接口时间参数的校验逻辑已补充回归用例，但仍需继续验证修复后的实际返回是否符合预期。

---

## 十、建议

1. 统一 `start` / `end` 的输入格式规范，并在接口入口强校验。
2. 非法时间参数必须返回 `400`，不要返回空列表。
3. 为时间戳、日期、日期时间、非法字符补齐自动化用例。
4. 日志类接口尽量复用同一套时间校验逻辑，避免分支差异。
