# Bug Report: Group 空名称创建返回服务器异常

**Bug ID**: BUG-GROUP-CREATE-001  
**标题**: POST `/cms/group` 传入空名称时返回 500 而非参数校验失败  
**模块**: 权限组管理  
**严重级别**: 中高  
**优先级**: P0  
**状态**: 已定位  
**发现日期**: 2026-06-16  
**提交人**: 测试团队 2号

---

## 一、问题概述

调用 `POST /cms/group` 新建权限组时，如果传入空名称（`name: ""`），接口返回 HTTP 500（`error_code: 1007`），而非返回参数校验失败提示。

该问题属于参数校验缺失——空名称应在 API 层被 Validator 拦截并提示"请输入分组名称"，但实际直接穿透到数据库层导致异常。

---

## 二、影响范围

### 受影响功能
- 权限组新建参数校验

### 受影响接口
- `POST /cms/group`

### 业务影响
- 前端用户可能输入空名称后看到"服务器错误"而非友好提示
- 异常被错误地归类为服务器端问题

## 六、预期结果

接口应返回参数校验失败，提示"请输入分组名称"或"name 不能为空"。

---

## 七、根因分析

### 1. 现象分析
- `create_group()` 使用 `get_request_args()` 直接从 request 提取参数（非 Validator），未对 name 字段做非空校验
- 空 name 直接传入 `GroupDao.create_group()` → `Group.create()`，在数据库写入时因 name 字段约束（NOT NULL 或 UNIQUE）触发异常

### 2. 关键代码
- [app/api/cms/group.py:46-50](app/api/cms/group.py#L46-L50)：`create_group()` 使用 `get_request_args()` 而非 Validator
- [app/dao/group.py](app/dao/group.py)：`create_group()` 直接调用 `Group.create()`
- [app/models/group.py](app/models/group.py)：`Group.create()` 写入数据库

### 3. 根因结论

**`create_group()` 使用 `get_request_args()` 提取参数而非专用 Validator，未对 `name` 字段做非空校验。** 空字符串 `""` 直接传入 `GroupDao.create_group(name="")` → `Group.create(name="")`，数据库 `name` 列有 UNIQUE 约束但允许空字符串，在 `Group.abort_repeat()` 或其他 UNIQUE 检查时触发内部异常。

**关键代码定位**：
- `app/api/cms/group.py:46-50`：`create_group()` 使用 `form = get_request_args()` 而非 Validator
- `app/core/utils.py:74-85`：`get_request_args()` 只过滤 `None` 值，不过滤空字符串
- `app/dao/group.py`：`create_group()` 直接传入 name 到 Model

---

## 八、修复方案

### 当前采取的修复策略
- 为 `POST /cms/group` 增加 Validator 校验，name 字段标记为 required
- 或将 `get_request_args()` 替换为专用 Form，校验 name 非空

### 后续推荐优化方向
- 统一定义 `CreateGroupValidator`，对 name、auth_ids 做完整校验
- 其他使用 `get_request_args()` 的接口也应审查是否有类似校验缺失
