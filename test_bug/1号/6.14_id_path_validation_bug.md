# Bug Report: 路径 ID 参数未统一做正整数校验

**Bug ID**: BUG-ID-VALIDATION-001  
**标题**: 多个传 `id` 的接口在非法路径参数下返回 404，而不是参数格式错误  
**模块**: 接口路由 / 参数校验 / CMS 管理端  
**严重级别**: 中高  
**优先级**: P1  
**状态**: 已修复  
**发现日期**: 2026-06-14  
**提交人**: 1号

---

## 一、问题概述

项目中多个带路径参数 `id` / `uid` 的接口，原先直接使用 Flask 的 `<int:...>` 路由转换器。这样一来，当请求路径中传入 `abc`、`0`、`-1` 等非法值时，请求会在路由层直接匹配失败并返回 `404`，而不是业务上期望的“参数格式错误”。

这会导致调用方无法区分“资源不存在”和“参数不合法”，也让接口错误语义不一致，影响前端提示和联调排查。

- 管理员管理

- `DELETE /cms/user/<uid>`
- `PUT /cms/user/<uid>/password`
- `GET /cms/route/<id>`
- `PUT /cms/route/<id>`
- `DELETE /cms/route/<id>`
- `GET /cms/banner_item/<id>`
- `PUT /cms/banner_item/<id>`
- `POST /cms/banner_item/<id>`

### 业务影响
- 非法 ID 被错误地表现为 404，掩盖参数错误
- 前端无法给出准确的“ID 格式不正确”提示
- 资源不存在与参数不合法的错误语义混淆
- 不同接口对 ID 校验规则不一致，维护成本增加

## 五、实际结果

在修复前，这些请求会被 Flask 路由层直接拦截，返回 `404 Not Found`。

示例：

```json
{
  "error_code": 404,
  "msg": "not found",
  "request_url": "/cms/log/login/abc"
}
```

实际返回形式会因全局错误处理配置略有差异，但核心问题是：非法 ID 被当成路由不存在，而不是参数格式错误。

---

## 六、预期结果

当路径参数 `id` / `uid` 非法时，接口应返回参数错误：

- `abc` 返回 `ID 必须为正整数`
- `0` 返回 `ID 必须为正整数`
- `-1` 返回 `ID 必须为正整数`
- 只有大于 0 的整数才允许继续进入业务逻辑

---

## 七、根因分析

### 1. 现象分析

接口路由使用了 `<int:...>` 转换器，导致非法字符串无法进入视图函数，错误在路由层就被吞掉了。

### 2. 关键代码 / 关键逻辑

- `app/api/cms/login_log.py`
- `app/api/cms/admin.py`
- `app/api/cms/user.py`
- `app/api/cms/route.py`
- `app/api/cms/banner_item.py`

### 3. 根因结论

问题根因是路径参数校验依赖 Flask 的类型转换器，导致非法 ID 无法在业务层统一处理，进而返回了不符合业务预期的 `404`。

---

## 八、修复方案

### 当前采取的修复策略
- 将带 ID 的路由从 `<int:...>` 调整为普通字符串参数
- 在接口内部统一增加 `_parse_positive_id(...)` 校验
- 对非法值统一抛出 `ParameterException(msg='ID 必须为正整数')`
- 确保 ID 必须大于 0 才能继续执行业务逻辑

### 后续推荐优化方向
- 将正整数 ID 校验抽成公共工具，避免各接口重复实现
- 为所有带 path ID 的接口统一错误码和错误文案
- 补齐 `abc`、`0`、负数等边界回归测试

---

## 九、修复结果

当前已修复相关接口的 ID 校验逻辑，非法路径参数不再被路由层直接吞掉，而是会返回统一的参数错误提示。相关接口现在要求 `id` 必须为正整数。

---

## 十、建议

1. 所有 path ID 参数统一改为业务层校验，不再依赖 `<int:...>`。
2. 正整数 ID 校验逻辑抽成公共函数，减少重复代码。
3. 对每个带 ID 的接口补齐非法值回归用例。
4. 统一前端提示文案，区分“参数错误”和“资源不存在”。
