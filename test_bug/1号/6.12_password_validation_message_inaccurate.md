# Bug Report: 密码校验失败提示文案与实际规则不一致

**Bug ID**: BUG-USER-PASSWORD-MSG-001  
**标题**: 密码参数校验失败时提示“包含字符、数字和 _”，与实际正则规则不一致  
**模块**: 用户管理 / 参数校验 / 密码校验  
**严重级别**: 低  
**优先级**: P2  
**状态**: 已修复  
**发现日期**: 2026-06-12
**提交人**: 测试团队 1号

---

## 一、问题概述

调用涉及密码校验的接口时，如果密码参数不符合规则，接口返回的错误提示为：

```json
{
  "error_code": 10120,
  "msg": {
    "new_password": [
      "密码长度必须在6~22位之间，包含字符、数字和 _ "
    ]
  },
  "request_url": "PUT /v1/user/password"
}
```

该提示文案容易被理解为密码必须同时包含字母、数字和下划线，但实际代码中的正则规则并没有强制同时包含这些字符，只要求密码长度为 6~22 位，且字符范围限定为字母、数字和部分特殊字符。

---

## 二、影响范围

### 受影响功能
- 用户注册密码校验
- 修改密码校验
- 重置密码校验
- 接口错误提示

### 受影响接口 / 页面
- `POST /v1/user`
- `PUT /v1/user/password`
- 其他复用 `CreatePasswordValidator` 或 `ResetPasswordValidator` 的接口

### 业务影响
- 错误提示与实际校验规则不一致
- 测试人员和前端使用方容易误解密码规则
- 用户可能认为纯数字密码不允许，但实际 `1234567` 可以通过校验
- 不利于接口文档和自动化用例保持一致

接口返回参数校验失败。

## 五、实际结果

修复前接口返回类似：

```json
{
  "error_code": 10120,
  "msg": {
    "new_password": [
      "密码长度必须在6~22位之间，包含字符、数字和 _ "
    ]
  },
  "request_url": "PUT /v1/user/password"
}
```

该提示容易让人理解为密码必须同时包含字符、数字和 `_`。

但实际正则为：

```python
r'^[A-Za-z0-9_*&$#@]{6,22}$'
```

其真实含义是：

- 长度 6~22 位
- 仅允许字母、数字和 `_ * & $ # @`
- 不强制同时包含字母、数字或下划线

因此 `1234567` 这类纯数字密码可以通过校验。

---

## 六、预期结果

错误提示应准确描述实际密码规则，例如：

```text
密码长度必须在6~22位之间，仅支持字母、数字和 _*&$#@
```

不应使用容易误解为“必须同时包含”的描述。

---

## 七、根因分析

### 1. 现象分析

密码校验正则实际只限制字符范围和长度，但提示文案使用了“包含字符、数字和 _”的表达。

### 2. 关键代码 / 关键逻辑

修复前，`CreatePasswordValidator` 和 `ResetPasswordValidator` 中的提示文案如下：

```python
Regexp(r'^[A-Za-z0-9_*&$#@]{6,22}$', message='密码长度必须在6~22位之间，包含字符、数字和 _ ')
```

其中正则并未表达“必须同时包含字母、数字和下划线”的规则。

### 3. 根因结论

问题根因是密码校验错误提示文案与实际正则规则描述不一致，属于提示文案准确性问题。

---

## 八、修复方案

### 当前采取的修复策略

将 `CreatePasswordValidator` 和 `ResetPasswordValidator` 中的密码校验提示文案统一修改为准确描述：

修复前：

```python
message='密码长度必须在6~22位之间，包含字符、数字和 _ '
```

修复后：

```python
message='密码长度必须在6~22位之间，仅支持字母、数字和 _*&$#@'
```

## 九、修复结果

当前问题已修复。

修复后，当密码包含不支持字符或长度不符合要求时，接口返回：

```json
{
  "error_code": 10120,
  "msg": {
    "new_password": [
      "密码长度必须在6~22位之间，仅支持字母、数字和 _*&$#@"
    ]
  },
  "request_url": "PUT /v1/user/password"
}
```

提示文案与实际校验规则一致。

---

## 十、建议

1. 接口文档中同步说明密码规则：长度 6~22 位，仅支持字母、数字和 `_ * & $ # @`。
2. 补充密码边界用例：长度 5、长度 6、长度 22、长度 23。
3. 补充非法字符用例，如 `!`、中文、空格、`.`、`-`。
4. 如果业务上希望强制密码同时包含字母和数字，应调整正则，而不是只修改提示文案。
