# Bug Report: 敏感信息泄露检查（Server/X-Powered-By 头）不会导致测试失败

**Bug ID**: BUG-ENV-LEAK-CHECK-001  
**标题**: `check_no_server_header` 和 `check_debug_mode` 仅通过 allure 记录发现结果，无 assert 断言，导致 TC-ENV-005 不会失败  
**模块**: 环境变量 / 安全检测 / 自动化测试  
**严重级别**: 中  
**优先级**: P1  
**状态**: 已定位  
**发现日期**: 2026-06-18  
**提交人**: 测试团队 4号

---

## 一、问题概述

4号环境变量测试中，TC-ENV-005（敏感信息泄露）通过 `check_no_server_header` 检查响应头中的 `Server` 和 `X-Powered-By` 字段，通过 `check_debug_mode` 检查响应中是否包含调试信息。然而这两个检查函数都**仅通过 `allure.attach` 记录发现结果，没有任何 `assert` 断言**。这意味着即使服务端存在敏感信息泄露（如暴露 `Server: Werkzeug` 或开启 DEBUG 模式），测试仍然会显示为 PASS。

---

## 二、影响范围

### 受影响功能
- 服务端安全配置检测
- 敏感信息泄露扫描
- DEBUG 模式检测

### 受影响接口
- `GET /`（检查 Server 头）
- `GET /apispec_1.json`（检查 DEBUG 信息）

### 业务影响
- 服务端暴露 `Server` / `X-Powered-By` 头时测试无法发现
- DEBUG 模式误开启时测试无法发现
- 安全检测形同虚设，提供虚假通过结果
- 可能遗漏生产环境安全隐患

- 环境：本地开发环境
- 服务地址：`http://127.0.0.1:5000`
- 测试文件：`tests/api/4号/test_env_cases.py`

## 四、复现步骤

### 步骤 1：查看 `check_no_server_header` 实现

```python
def check_no_server_header(resp, case):
    """检查响应头中不应包含 Server / X-Powered-By"""
    server = resp.headers.get("Server")
    powered_by = resp.headers.get("X-Powered-By")
    if server:
        allure.attach(str(server), "发现 Server 头", allure.attachment_type.TEXT)
    if powered_by:
        allure.attach(str(powered_by), "发现 X-Powered-By 头", allure.attachment_type.TEXT)
    # 无 assert
```

### 步骤 2：查看 `check_debug_mode` 实现

```python
def check_debug_mode(resp, case):
    """检查是否泄露 DEBUG 信息"""
    text = resp.text.lower()
    if "traceback" in text or "debug" in text:
        allure.attach(resp.text[:500], "疑似 DEBUG 信息", allure.attachment_type.TEXT)
    # 无 assert
```

### 步骤 3：运行 TC-ENV-005

即使 `Server: Werkzeug/3.0.1 Python/3.12.0` 存在于响应头中，测试结果为 PASS。

---

## 五、实际结果

`check_no_server_header` 和 `check_debug_mode` 仅记录信息，不会导致测试失败。

---

## 六、预期结果

当检测到敏感信息泄露时，测试应失败并明确指出泄露的具体内容：

```python
def check_no_server_header(resp, case):
    server = resp.headers.get("Server")
    powered_by = resp.headers.get("X-Powered-By")
    assert server is None, f"响应头泄露 Server 信息: {server}"
    assert powered_by is None, f"响应头泄露 X-Powered-By 信息: {powered_by}"
```

## 七、根因分析

### 1. 现象分析

两个检查函数的本意是安全扫描，但实现时只做了检测和记录，遗漏了断言步骤。

### 2. 关键代码

```python
# tests/api/4号/test_env_cases.py
def check_no_server_header(resp, case):
    server = resp.headers.get("Server")
    if server:
        allure.attach(...)  # 只记录，不断言

def check_debug_mode(resp, case):
    if "traceback" in text or "debug" in text:
        allure.attach(...)  # 只记录，不断言
```

### 3. 根因结论

安全检查函数缺少 `assert` 断言，属于测试代码逻辑缺陷。

---

## 八、修复方案

### 推荐修复

为两个检查函数增加断言：

```python
def check_no_server_header(resp, case):
    server = resp.headers.get("Server")
    powered_by = resp.headers.get("X-Powered-By")
    if server:
        allure.attach(str(server), "发现 Server 头", allure.attachment_type.TEXT)
    if powered_by:
        allure.attach(str(powered_by), "发现 X-Powered-By 头", allure.attachment_type.TEXT)
    assert server is None, f"安全风险：响应头包含 Server={server}"
    assert powered_by is None, f"安全风险：响应头包含 X-Powered-By={powered_by}"

def check_debug_mode(resp, case):
    text = resp.text.lower()
    has_traceback = "traceback" in text
    has_debug = "debug" in text
    if has_traceback or has_debug:
        allure.attach(resp.text[:500], "疑似 DEBUG 信息", allure.attachment_type.TEXT)
    assert not has_traceback, "安全风险：响应中包含 traceback 信息"
    assert not has_debug, "安全风险：响应中包含 debug 信息"
```

### 后续推荐
- 根据环境区分断言策略：开发环境允许暴露调试信息，生产/测试环境应严格拦截
- 增加更多安全头检查（如 `X-Content-Type-Options`, `X-Frame-Options`）

## 十、建议

1. 所有安全检查函数必须有 `assert`，不能仅依赖 allure 记录
2. 将安全检测结果分为"必须拦截"和"建议修复"两级，对应不同断言策略
3. 排查其他测试文件中是否存在类似的"只记录不断言"模式
4. 在 CI 中增加安全扫描步骤，不依赖功能测试覆盖
