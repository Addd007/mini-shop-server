# Bug Report: 商品图片排序接口边界参数校验缺失

**Bug ID**: BUG-PROD-REORDER-001  
**标题**: `PUT /v1/product/{id}/reorder` 未正确校验相同顺序和超范围顺序，可能返回错误提示或错误移动图片  
**模块**: 商品管理 / 商品图片排序  
**严重级别**: 中高  
**优先级**: P1  
**状态**: 已定位  
**发现日期**: 2026-06-11  
**提交人**: 测试团队 1号

---

## 一、问题概述

调用商品图片排序接口 `PUT /v1/product/{id}/reorder` 时，接口对 `src_order` 和 `dest_order` 的边界参数校验不足，存在以下异常现象：

1. 当 `src_order` 与 `dest_order` 相同时，接口返回错误：`该商品仅有一张图片，无法重新排序`，但该提示并不准确。
2. 当 `dest_order` 超出实际图片顺序范围时，接口仍返回成功，并将源图片移动到实际末尾。
3. 当 `src_order` 超出实际图片顺序范围时，接口仍返回成功，并错误地将实际末尾图片移动到目标位置。

其中第 2、3 类问题会造成用户传入无效排序位置时，系统仍修改真实图片顺序，可能导致商品图片排序被错误变更。

## 五、实际结果

### 场景一：`src_order` 与 `dest_order` 相同

接口返回如下错误：

```json
{
  "error_code": 30000,
  "msg": "该商品仅有一张图片，无法重新排序",
  "request_url": "PUT /v1/product/11/reorder"
}
```

该错误提示与实际请求语义不匹配。当前请求并不能说明商品只有一张图片，只能说明源顺序和目标顺序相同。

### 场景二：`dest_order` 超出范围

请求 Body：

```json
{
  "dest_order": 113,
  "src_order": 3
}
```

接口返回成功，并将 `src_order=3` 的图片移动到实际图片列表末尾。

### 场景三：`src_order` 超出范围

请求 Body：

```json
{
  "dest_order": 3,
  "src_order": 300
}
```

接口返回成功，并将实际末尾图片移动到 `order=3` 的位置。

该场景风险较高，因为请求指定的 `src_order=300` 图片并不存在，但系统仍修改了实际存在的末尾图片顺序。

## 六、预期结果

当 `src_order` 与 `dest_order` 相同时，系统应识别为无变化操作。

推荐预期结果之一：直接返回成功，不修改数据：

```json
{
  "error_code": 1,
  "msg": "创建 | 更新成功",
  "data": null
}
```

或返回明确业务提示：

```json

  "error_code": 30000,
  "msg": "源顺序和目标顺序相同，无需重新排序",
  "request_url": "PUT /v1/product/11/reorder"

```

当 `src_order` 或 `dest_order` 超出商品实际图片顺序范围时，系统应拒绝请求并返回明确参数错误，例如：

```json
{
  "error_code": 10120,
  "msg": "src_order 超出商品图片顺序范围",
  "request_url": "PUT /v1/product/11/reorder"
}
```

或：

```json
{
  "error_code": 10120,
  "msg": "dest_order 超出商品图片顺序范围",
  "request_url": "PUT /v1/product/11/reorder"
}
```

接口不应在源顺序或目标顺序不存在时仍返回成功，更不应移动其他真实存在的图片。

## 七、根因分析

### 1. 现象分析

该问题不是权限不足或商品不存在导致的错误，而是排序逻辑对边界参数处理不准确。

当 `src_order == dest_order` 时，排序范围被计算为单个位置，例如 `order between 1 and 1`，查询结果只包含一张图片。当前代码将“排序范围内图片数量小于等于 1”直接解释为“该商品仅有一张图片”，因此返回了不准确的错误信息。

当 `dest_order` 超出范围时，例如 `src_order=3`、`dest_order=113`，查询范围为 `order between 3 and 113`。如果实际图片只有 5 张，查询结果只会包含 `order=3` 到 `order=5` 的图片，代码会把 `order=3` 的图片移动到查询结果最后一张的位置，即实际末尾。

当 `src_order` 超出范围时，例如 `src_order=300`、`dest_order=3`，查询范围为 `order between 3 and 300`。如果实际图片只有 5 张，查询结果只会包含 `order=3` 到 `order=5` 的图片，代码会把查询结果最后一张图片当作源图片移动到 `order=3`，导致真实末尾图片被错误移动。

### 2. 关键代码 / 关键逻辑

商品图片排序逻辑位于 `app/dao/product.py`：

```python
[min, max] = sorted([src_order, dest_order])
pending_reorder_list = Product2Image.query.filter(
    Product2Image.product_id == p_id,
    Product2Image.order.between(min, max)
).order_by(Product2Image.order.asc()).all()

if len(pending_reorder_list) <= 1:
    raise ProductException(msg='该商品仅有一张图片，无法重新排序')
```

当请求参数为：

```json
{
  "src_order": 1,
  "dest_order": 1
}
```

排序区间为：

```text
order between 1 and 1
```

因此查询结果最多只有一条记录，从而触发：

```python
raise ProductException(msg='该商品仅有一张图片，无法重新排序')
```

### 3. 根因结论

问题根因是排序接口缺少对 `src_order == dest_order`、`src_order` 是否存在、`dest_order` 是否存在的前置判断，并且使用排序区间查询结果的首尾元素直接作为移动对象。

因此，当传入相同顺序或超范围顺序时，接口没有按参数语义进行校验，而是基于实际查询结果继续执行排序，导致错误提示不准确或错误移动真实图片。

## 八、修复方案

### 当前采取的修复策略
- 当前已完成问题定位，尚未进行代码修复。
- 测试侧应将该边界场景记录为缺陷，不应将错误提示视为合理结果。

### 后续推荐优化方向
- 在 `ProductDao.reorder_image` 开始处增加前置判断：当 `src_order == dest_order` 时直接返回，不进行数据库更新。
- 查询并校验 `src_order` 对应的图片是否存在，不存在时返回明确参数错误。
- 查询并校验 `dest_order` 对应的图片是否存在，不存在时返回明确参数错误。
- 如果业务允许 `dest_order` 超出范围自动放到末尾，需要在接口文档中明确说明，并避免 `src_order` 不存在时误移动末尾图片。
- 区分“商品真实图片数量不足”“源顺序不存在”“目标顺序不存在”“源顺序和目标顺序相同”等不同错误场景。
- 增加参数范围校验，确保 `src_order` 和 `dest_order` 对应的图片顺序存在。

---

## 九、修复结果

当前状态：已定位，待修复。

修复完成后，应重新验证以下场景：

- `src_order == dest_order` 时接口返回成功或明确无需排序提示。
- `src_order < dest_order` 且两者都存在时图片可向后移动。
- `src_order > dest_order` 且两者都存在时图片可向前移动。
- `dest_order` 超出范围时接口返回明确参数错误，或符合文档约定的末尾移动行为。
- `src_order` 超出范围时接口返回明确参数错误，不应移动实际末尾图片。
- 商品真实只有一张图片时，接口返回准确提示。
- `src_order` 或 `dest_order` 不存在时，接口返回明确参数错误。

---

## 十、建议

1. 将 `src_order == dest_order` 作为图片排序接口的边界测试用例。  
2. 将 `src_order` 超出范围、`dest_order` 超出范围作为异常测试用例。  
3. 对排序类接口增加幂等性设计，位置不变时建议直接返回成功。  
4. 错误提示应描述真实原因，避免用查询区间结果推断商品图片总数。  
5. 增加商品图片总数校验和排序位置存在性校验。  
6. 补充自动化测试覆盖相同顺序、正向移动、反向移动、非法顺序等场景。

## 十五、结论

该问题属于商品图片排序接口边界参数校验缺陷，已定位到 `ProductDao.reorder_image` 缺少 `src_order == dest_order`、源顺序存在性和目标顺序存在性的前置判断。当前实现会在相同顺序场景返回误导性错误，也会在超范围顺序场景错误移动真实图片。建议按 P1 优先级修复，并补充排序接口边界参数测试，避免非法请求造成商品图片顺序异常。
