## 一、更新说明（2026-06-19）

### 之前的问题

历史上 `check_tags` 函数只验证标签非空（`assert len(tag_names) > 0`），从未将实际标签与 `EXPECTED_SWAGGER_MODULES` 做对比，导致 `EXPECTED_SWAGGER_MODULES` 是死代码。

### 当前状态：测试代码已修复

当前测试代码已正确实现标签完整性验证：

```python
# tests/api/4号/test_swagger_cases.py
critical_tags = ["v1-token", "cms-admin", "cms-file", 
                  "v1-user", "v1-product", "v1-order"]
missing_critical = [t for t in critical_tags if t not in tag_names]
assert not missing_critical, f"[{case['id']}] Swagger 缺少核心标签: {missing_critical}"
```

### 新发现：真实缺陷

TC-SWAG-005 **FAILED**，Swagger 文档缺少 6 个核心标签：

```
AssertionError: [TC-SWAG-005] Swagger 缺少核心标签: 
  ['v1-token', 'cms-admin', 'cms-file', 'v1-user', 'v1-product', 'v1-order']
```

---

## 二、影响

| 缺失标签 | 对应模块 | 影响 |
|----------|----------|------|
| `v1-token` | 认证 Token 接口 | Swagger UI 中无 Token 相关接口 |
| `cms-admin` | CMS 管理员接口 | Swagger UI 中无管理员管理接口 |
| `cms-file` | 文件管理 CMS 接口 | Swagger UI 中无文件管理接口 |
| `v1-user` | V1 用户接口 | Swagger UI 中无用户相关接口 |
| `v1-product` | V1 商品接口 | Swagger UI 中无商品相关接口 |
| `v1-order` | V1 订单接口 | Swagger UI 中无订单相关接口 |

---

## 三、可能原因

### 代码分析

标签来源于 `@api.doc(tags=['v1-token'])` 装饰器。可能原因：
1. 这些模块的 blueprint 未注册到 Swagger（`flasgger` / `apispec`）中
2. 路由使用了不规范的 tags 命名
3. `apispec` 插件未扫描到这些 blueprint

### 排查步骤

检查 `app/api/v1/` 和 `app/api/cms/` 下的路由装饰器：
```python
# 正确示例
@api.route('/token', methods=['POST'])
@api.doc(tags=['v1-token'])
def create_token():
    ...
```

---

## 四、修复建议

1. 确认对应模块的 blueprint 已注册到 Swagger scope
2. 检查每个路由的 `@api.doc(tags=[...])` 装饰器是否正确
3. 如果某些标签确实不存在（接口未实现），从 `EXPECTED_SWAGGER_MODULES` 或 `critical_tags` 中移除
