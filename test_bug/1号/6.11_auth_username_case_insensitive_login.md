# Bug Report: 用户名登录大小写不匹配仍可登录成功

**Bug ID**: BUG-AUTH-USERNAME-CASE-001  
**标题**: `POST /v1/token` 用户名大小写不匹配时仍登录成功  
**模块**: 认证鉴权 / 用户名登录  
**严重级别**: 中  
**优先级**: P2  
**状态**: 已修复  
**发现日期**: 2026-06-11  
**提交人**: 测试团队 1号

---

## 一、问题概述

调用登录接口 `POST /v1/token` 使用用户名登录时，数据库中实际用户名为 `super`，但请求中传入 `Super` 也可以登录成功。

该问题说明用户名登录校验未严格区分大小写。对于用户名字段，如果业务要求用户名必须精确匹配，则大小写不一致时应登录失败，否则可能造成账号识别不严格、测试预期不一致等问题。

---

### 受影响功能
- 用户名登录

- 异常登录用例
- 账号安全校验

### 受影响接口 / 页面
- `POST /v1/token`

### 业务影响

- 异常登录测试用例结果与预期不符
- 账号匹配逻辑依赖数据库排序规则，行为不够明确
- 如果存在大小写相近账号，可能造成账号识别风险

## 五、实际结果

修复前，虽然传入的用户名是 `Super`，与数据库中的 `super` 大小写不一致，但接口仍返回登录成功，例如：

```json

  "error_code": 0,
  "msg": "成功",
  "data": {
    "token": "<token>"
  }
}
```

---

## 六、预期结果

当用户名大小写与数据库中保存的用户名不完全一致时，应登录失败，并返回用户名不存在或登录失败，例如：

```json
{
  "error_code": 21000,
  "msg": "该用户名未注册",
  "request_url": "POST /v1/token"
}
```

或者根据业务规范返回统一登录失败提示。

---

## 七、根因分析

### 1. 现象分析

该问题不是密码校验缺失导致的，因为密码仍然需要正确匹配。

问题发生在用户名查询阶段。数据库查询使用 `identifier=username` 进行匹配，但数据库字符串比较很可能使用大小写不敏感的排序规则，例如 `utf8_general_ci` 或 `utf8mb4_general_ci`。在此类排序规则下：

```sql
identifier = 'Super'
```

可以匹配到：

```text
super
```

因此后续密码校验通过后，接口会签发 Token。

### 2. 关键代码 / 关键逻辑

修复前用户名登录逻辑：

```python
identity = Identity.get_or_404(identifier=username, type=ClientTypeEnum.USERNAME.value,
                               e=IdentityException(msg='该用户名未注册'))
identity.check_password(password, e=AuthFailed(msg='密码错误'))
user = User.get(id=identity.user_id)
return {'uid': user.id, 'scope': user.auth_scope}
```

该逻辑完全依赖数据库查询结果，没有在应用层确认用户输入的用户名与数据库返回的 `identity.identifier` 是否完全一致。

### 3. 根因结论

问题根因是用户名查询依赖数据库默认字符串比较规则，而数据库排序规则大小写不敏感，导致 `Super` 可以匹配 `super`。应用层没有进行二次精确大小写校验。

---

## 八、修复方案

### 当前采取的修复策略

已在用户名登录逻辑中增加 Python 字符串精确比较，确保输入用户名与数据库返回用户名完全一致。

修复后代码：

```python
identity = Identity.get_or_404(identifier=username, type=ClientTypeEnum.USERNAME.value,
                               e=IdentityException(msg='该用户名未注册'))
if identity.identifier != username:
    raise IdentityException(msg='该用户名未注册')
identity.check_password(password, e=AuthFailed(msg='密码错误'))
```

### 后续推荐优化方向
- 明确业务规则：用户名是否区分大小写。
- 如果用户名必须区分大小写，建议数据库字段使用大小写敏感排序规则，或在查询时使用二进制比较。
- 如果业务希望用户名不区分大小写，则应在用例和文档中明确说明，并删除大小写不匹配失败用例。
- 对邮箱登录是否大小写敏感也应单独明确规则。

## 九、修复结果

当前问题已修复。

修复后，请求：

```json
{
  "account": "Super",
  "secret": "123456",
  "type": 100
}
```

不应再登录成功，应返回用户名未注册或统一登录失败提示。

---

## 十、建议

1. 将用户名大小写不匹配场景纳入登录异常回归测试。  
2. 在接口文档中明确用户名大小写规则。  
3. 对 `identity.identifier` 的数据库排序规则进行检查，确认是否符合业务预期。  
4. 对用户名、邮箱、手机号三类登录方式分别明确大小写/格式匹配规则。
