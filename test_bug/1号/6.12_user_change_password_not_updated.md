# Bug Report: 修改密码接口返回成功但数据库密码未更新

**Bug ID**: BUG-USER-CHANGE-PASSWORD-001  
**标题**: `PUT /v1/user/password` 修改密码时可能返回成功但数据库密码未更新，或旧密码正确却返回密码错误  
**模块**: 用户管理 / 修改密码  
**严重级别**: 中  
**优先级**: P1  
**状态**: 已修复  
**发现日期**: 2026-06-12  
**提交人**: 测试团队 1号

---

## 一、问题概述

调用修改密码接口 `PUT /v1/user/password` 时，请求参数合法，接口返回「创建 | 更新成功」，但数据库中的密码凭证没有变化。

进一步验证发现，同一账号可以通过旧密码正常登录，但调用修改密码接口时可能返回「密码错误」。该问题会导致用户以为密码已修改成功，但实际仍然只能使用旧密码登录，影响账号安全和用户体验。

---

## 二、影响范围

### 受影响功能
- 当前用户修改密码
- 用户名 / 邮箱 / 手机号多身份密码同步
- 旧密码校验
- 接口成功状态准确性

### 受影响接口 / 页面
- `PUT /v1/user/password`

### 业务影响
- 接口返回成功但密码未实际修改
- 用户无法确认密码是否真正变更
- 多登录身份密码不一致时，旧密码校验可能误判失败
- 自动化测试可能只判断响应成功，无法发现数据库未更新

```json

  "new_password": "1234567",
  "old_password": "123456"
```

接口返回「密码错误」。

## 六、预期结果

### 旧密码正确时

应成功修改密码，并同步更新当前用户所有站内登录方式的密码凭证：

- 用户名登录
- 邮箱登录
- 手机号登录

接口返回更新成功，数据库中的 `identity.credential` 应更新为新密码的 SHA256 值。

### 旧密码错误时

应返回明确错误：

```json
{
  "error_code": 10000,
  "msg": "密码错误",
  "request_url": "PUT /v1/user/password"
}
```

不应返回更新成功。

### 当前用户没有站内登录方式时

应返回明确业务错误，例如：

```json
{
  "error_code": 20000,
  "msg": "当前用户没有可修改密码的登录方式",
  "request_url": "PUT /v1/user/password"
}
```

## 七、根因分析

### 1. 现象分析

该问题与请求参数无关，参数校验层能够正常通过。问题发生在修改密码的业务逻辑中。

### 2. 关键代码 / 关键逻辑

修复前，`UserDao.change_password` 中先通过 `Identity.get_or_404(user_id=uid)` 查询当前用户任意一条身份记录：

```python
@staticmethod
def change_password(uid, old_password, new_password):
    identity = Identity.get_or_404(user_id=uid)  # 找到一个
    if identity.check_password(old_password):
        identity_list = Identity.query.filter(
            Identity.type.in_([
                ClientTypeEnum.USERNAME.value,
                ClientTypeEnum.EMAIL.value,
                ClientTypeEnum.MOBILE.value]),
            Identity.user_id == uid
        ).all()
        with db.auto_commit():
            for item in identity_list:
                item.update(commit=False, password=new_password)
```

该逻辑存在两个问题：

1. `Identity.get_or_404(user_id=uid)` 没有限定登录类型，可能查到微信等非站内登录身份，导致旧密码校验失败。
2. 当 `identity.check_password(old_password)` 返回 `False` 时，方法直接结束，没有抛出异常，接口层仍然返回更新成功。

此外，同一用户可能存在用户名、邮箱、手机号多条站内身份。如果这些身份的密码凭证不一致，只校验第一条有密码的身份，也可能出现「用户名登录成功，但修改密码提示密码错误」的问题。

### 3. 根因结论

问题根因是修改密码逻辑对身份记录选择不准确，并且旧密码校验失败时没有抛出业务异常，导致接口响应与实际数据库更新状态不一致。

---

## 八、修复方案

### 当前采取的修复策略

已调整 `UserDao.change_password`：

1. 只查询当前用户的站内登录身份：用户名、邮箱、手机号。
2. 如果没有站内登录身份，返回「当前用户没有可修改密码的登录方式」。
3. 对所有有密码的站内身份进行旧密码校验，只要任意一条通过，即认为旧密码有效。
4. 如果所有站内身份均校验失败，返回「密码错误」。
5. 校验通过后，同步更新所有站内身份的密码。

修复后关键逻辑：

```python
identity_list = Identity.query.filter(
    Identity.type.in_([
        ClientTypeEnum.USERNAME.value,
        ClientTypeEnum.EMAIL.value,
        ClientTypeEnum.MOBILE.value]),
    Identity.user_id == uid
).all()
if not identity_list:
    raise UserException(msg='当前用户没有可修改密码的登录方式')

password_identities = [item for item in identity_list if item.password]
if not password_identities:
    raise UserException(msg='当前用户没有可修改密码的登录方式')
if not any(item.check_password(old_password) for item in password_identities):
    raise AuthFailed(msg='密码错误')

with db.auto_commit():
    for item in identity_list:
        item.update(commit=False, password=new_password)
```

### 后续推荐优化方向
- 确保同一用户的用户名、邮箱、手机号三类站内身份密码始终保持一致。
- 为修改密码接口增加数据库层面的断言，不能只判断接口返回成功。
- 对 `Identity.get_or_404(user_id=uid)` 这类未限定身份类型的查询进行排查。

## 九、修复结果

当前问题已修复。

修复后再次请求：

```json
{
  "confirm_password": "1234567",
  "new_password": "1234567",
  "old_password": "123456"
}
```

如果当前用户任意一个站内身份的密码是 `123456`，接口应返回更新成功，并将该用户所有站内身份密码同步更新为 `1234567` 的 SHA256 值。

如果旧密码不匹配，则返回「密码错误」，不再出现返回成功但数据库未更新的情况。

## 十、建议

1. 为修改密码接口补充用例：旧密码正确修改成功，并验证数据库密码已变化。
2. 补充旧密码错误用例，确认接口返回「密码错误」。
3. 补充多身份密码不一致场景，确认任意站内身份旧密码匹配时可同步更新所有站内身份。
4. 修改密码后，应使用新密码重新登录验证，同时确认旧密码无法登录。
5. 后续可考虑在数据初始化和账号绑定逻辑中，统一保证同一用户站内身份密码一致。
