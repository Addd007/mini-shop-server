# Bug Report: 新建文件夹 `POST /cms/file/new` 返回 500 服务器端异常

**Bug ID**: BUG-FILE-FOLDER-500-001  
**标题**: `POST /cms/file/new` 新建文件夹接口返回 `error_code: 999` 服务器端异常  
**模块**: 文件管理 / 文件夹操作  
**严重级别**: 高  
**优先级**: P0  
**状态**: 已定位  
**发现日期**: 2026-06-18  
**提交人**: 测试团队 4号

---

## 一、问题概述

TC-FILE-013（新建文件夹）和 TC-FILE-027/028（文件夹上传与移动）中调用 `POST /cms/file/new` 创建文件夹时，接口返回 500 服务器端异常：

```json
{"error_code": 999, "msg": "服务器端异常", "request_url": "POST /cms/file/new"}
```

这导致新建文件夹和依赖文件夹的后续操作（上传到文件夹、移动到文件夹）均无法验证。

---

## 二、影响范围

### 受影响功能
- 新建文件夹
- 上传文件到指定文件夹
- 文件移动到文件夹

### 受影响接口
- `POST /cms/file/new`
- 依赖文件夹的 `POST /cms/file/{folder_id}`
- 依赖文件夹的 `PUT /v1/file/{id}/move`

### 业务影响
- 文件夹创建功能不可用
- 3 个测试用例失败（TC-FILE-013, TC-FILE-027, TC-FILE-028）
- 文件组织结构化管理功能受阻

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地开发环境
- 服务地址：`http://127.0.0.1:5000`
- 测试文件：`tests/api/4号/test_file_cases.py`

---

## 四、复现步骤

### 步骤 1：获取管理员 Token

```json
{"account": "admin", "secret": "admin123456", "type": 100}
```

### 步骤 2：调用新建文件夹接口

```text
POST /cms/file/new?parent_id=0&filename=test_folder
Authorization: Bearer <token>
```

### 步骤 3：观察返回

```json
{
  "error_code": 999,
  "msg": "服务器端异常",
  "request_url": "POST /cms/file/new"
}
```

## 五、实际结果

|------|------|------|------|
| TC-FILE-013 | 新建文件夹 | 500 | 200 |
| TC-FILE-027 | 文件夹上传与移动（第1步） | 500 | 200 |

---

## 六、预期结果

新建文件夹应返回 200，并返回文件夹 ID 等信息。

---

## 七、根因分析

### 1. 现象分析

该问题与文件上传 500 异常可能同源，都是文件/文件夹写操作失败。可能原因：

- 文件存储目录不可写
- 数据库 file 表写入失败
- 文件夹创建逻辑中依赖的配置缺失

### 2. 关键代码

- `app/api/cms/file.py` — 新建文件夹视图
- `app/dao/file.py` — 文件/文件夹数据库操作

### 3. 根因结论

文件夹创建与文件上传可能共享同一底层存储/数据库逻辑，需与 BUG-FILE-UPLOAD-500-001 联合排查。

---

## 八、修复方案

### 排查步骤

1. 检查服务端日志（`logs/` 目录）
2. 确认数据库 file 表可正常写入
3. 确认 `media/` 目录可写
