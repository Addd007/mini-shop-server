# Bug Report: 更新商品接口返回成功但未实际更新商品数据

**Bug ID**: BUG-PROD-UPDATE-001  
**标题**: `PUT /v1/product/{id}` 更新商品接口为空实现，返回成功但商品数据未变化  
**模块**: 商品管理 / 商品更新  
**严重级别**: 中高  
**优先级**: P1  
**状态**: 已修复  
**发现日期**: 2026-06-11  
**提交人**: 测试团队 1号

---

## 一、问题概述

调用商品更新接口 `PUT /v1/product/{id}` 时，接口会直接返回更新成功，但实际没有读取请求参数，也没有更新数据库中的商品记录。

该问题会导致调用方误以为商品信息已经更新成功，但数据库中的商品名称、价格、库存、描述、分类等字段均未发生变化，属于典型的“接口假成功 / 空实现”问题。

---

## 二、影响范围

### 受影响功能
- 商品信息更新
- 后台商品管理
- 商品维护回归测试
- 依赖商品数据变更的前端展示与后续业务流程

### 受影响接口 / 页面
- `PUT /v1/product/{id}`
- 商品管理后台中的商品编辑功能，如果前端对接该接口

### 业务影响
- 管理员无法真正修改商品信息
- 接口返回成功会误导前端和测试人员
- 商品数据无法按业务要求维护
- 自动化测试如果只校验状态码，可能误判为通过

## 五、实际结果

更新接口返回成功，例如：

```json
{
  "error_code": 1,
  "msg": "创建 | 更新成功",
  "data": null
}
```

但再次查询商品详情时，商品数据未发生变化。

从代码实现看，接口当前只直接返回成功：

```python
def update_product(id):
    '''更新商品'''
    return Success(error_code=1)
```

对应 DAO 层也没有实际更新逻辑：

```python
def update_product():
    pass
```

---

## 六、预期结果

调用 `PUT /v1/product/{id}` 时，系统应：

1. 校验当前用户是否具备商品更新权限。
2. 校验路径参数 `id` 是否对应有效商品。
3. 校验请求 Body 中的商品更新字段是否合法。
4. 将允许更新的字段写入 `product` 表。
5. 返回明确的更新成功响应。
6. 再次查询商品详情时，应能看到更新后的商品数据。

如果商品不存在，应返回明确的商品不存在错误，而不是直接成功。

## 七、根因分析

### 1. 现象分析

该问题不是鉴权失败导致的异常，因为接口在权限通过后会返回成功。

问题在于接口返回成功并不代表业务逻辑执行成功。当前 `update_product` 方法没有任何更新逻辑，也没有调用 DAO 层更新方法。

### 2. 关键代码 / 关键逻辑

接口层 `app/api/v1/product.py` 中，更新商品接口只返回成功：

```python
@api.route('/<int:id>', methods=['PUT'])
@api.route_meta(auth='更新商品', module='商品')
@api.doc(args=['g.path.product_id'], auth=True)
@auth.group_required
def update_product(id):
    '''更新商品'''
    return Success(error_code=1)
```

DAO 层 `app/dao/product.py` 中，更新方法为空实现：

```python
@staticmethod
def update_product():
    pass
```

因此，无论请求 Body 传入什么商品字段，系统都不会读取或写入数据库。

### 3. 根因结论

问题根因是商品更新接口和 DAO 层均未实现实际更新逻辑，但接口仍返回更新成功，导致商品更新功能出现假成功。

## 八、修复方案

### 当前采取的修复策略
- 当前已完成问题定位，尚未实现业务修复。
- 测试侧应将该用例标记为失败或阻塞，不应仅根据返回成功判断通过。

### 后续推荐优化方向
- 新增商品更新参数校验器，例如 `UpdateProductValidator`。
- 在接口层读取并校验 Body 参数。
- 在 DAO 层实现 `ProductDao.update_product(id, form)`。
- 更新前校验商品是否存在。
- 只允许更新白名单字段，避免误改系统字段。
- 更新成功后建议返回更新后的商品数据，方便测试校验。

## 十、建议

1. 将“接口是否返回成功”和“业务数据是否实际变化”都纳入测试断言。  
2. 对新增、更新、删除类接口补充数据库前后置校验。  
3. 对空实现接口统一排查，避免类似假成功问题继续存在。  
4. 完善商品管理模块的接口文档，明确可更新字段和参数格式。  
5. 为 `ProductDao.create_product` 和 `ProductDao.update_product` 补充实现或明确标记为未开放功能。
