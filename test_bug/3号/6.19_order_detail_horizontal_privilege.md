# Bug Report: 订单详情水平越权

**Bug ID**: BUG-ORDER-AUTH-001  
**标题**: 普通用户可通过订单ID查看其他用户完整订单详情  
**模块**: 订单系统 / 鉴权  
**严重级别**: 高  
**优先级**: P0  
**状态**: 已定位 / 未修复  
**发现日期**: 2026-06-19  
**提交人**: 测试团队3号

---

## 一、问题概述

普通用户登录后调用 `GET /v1/order/{id}`，只要猜中或枚举到其他用户的订单ID，即可获取对方完整订单数据。响应包含用户ID、订单号、商品快照、收货姓名、手机号和详细地址等敏感信息。

该问题属于水平越权（IDOR），具有明显的隐私泄露风险。

---

## 二、影响范围

- 用户订单详情查询
- 订单号、商品及金额数据
- 收件人姓名、手机号和收货地址
- 所有可被枚举ID的用户订单

受影响接口：`GET /v1/order/{id}`。

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地测试环境
- 服务地址：`http://127.0.0.1:5000`
- 数据库：MySQL 8.0.41 / `zerd`
- Python：3.11.15
- 当前登录账号：`user`，用户ID 31
- 被访问订单：订单ID 28，实际属于用户ID 3

---

2. 使用该Token请求 `GET /v1/order/28`。
3. 观察HTTP状态码与返回数据中的 `user_id`。

## 六、预期结果

用户只能查询自己的订单。查询其他用户订单时应返回403或404，且不得返回任何订单和地址信息。

---

## 七、根因分析

`get_order()` 虽然使用了 `@auth.login_required`，但只检查用户是否登录。查询语句为：

```python
order = Order.query.get_or_404(id).hide('prepay_id')
```

该查询没有附加 `user_id=g.user.id` 条件，也没有调用订单所有权校验逻辑。因此任意登录用户都可以读取任意订单ID。

---

## 八、修复建议

1. 使用订单ID和当前用户ID联合查询：

```python
order = Order.query.filter_by(id=id, user_id=g.user.id).first_or_404()
```

2. 或复用统一的资源所有权校验方法。
3. 对订单列表、详情、支付和取消等接口统一审查水平越权。
4. 错误响应建议统一返回404，避免暴露订单是否存在。
