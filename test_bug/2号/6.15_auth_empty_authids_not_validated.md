# Bug Report: Auth Append 空 auth_ids 未被校验

**Bug ID**: BUG-AUTH-APPEND-001  
**标题**: PUT `/cms/auth/append` 传入空 `auth_ids: []` 时未做参数校验，直接返回成功  
**模块**: 权限分配管理  
**严重级别**: 中  
**优先级**: P1  
**状态**: 已定位  
**发现日期**: 2026-06-15  
**提交人**: 测试团队 2号

---

## 一、问题概述

调用 `PUT /cms/auth/append` 为权限组新增权限时，传入空数组 `auth_ids: []`，接口返回 HTTP 201 + `error_code: 1`（成功），而非返回参数校验失败提示"请输入 auths 字段"。

空 `auth_ids` 请求无实际意义——不会添加任何权限，但接口仍返回成功，会给调用方造成操作已生效的误导。

---

### 受影响功能
- 权限新增参数校验

### 受影响接口
- `PUT /cms/auth/append`

### 业务影响
- 调用方可能认为权限已分配，实际没有添加任何权限
- 参数语义不明确，缺少前端校验提示

## 四、复现步骤

### 步骤 1：获取管理员 Token
```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:5000/v1/token \
  -H "Content-Type: application/json" \
  -d '{"account":"super","secret":"123456","type":100}' \
  | python -c "import sys,json; print(json.load(sys.stdin)['data']['token'])")
```

### 步骤 2：传入空 auth_ids
```bash
curl -s -X PUT http://127.0.0.1:5000/cms/auth/append \
  -H "Content-Type: application/json" -u "$TOKEN:132" \
  -d '{"group_id":2,"auth_ids":[]}'
```

### 步骤 3：观察结果
返回 HTTP 201，`error_code: 1`（成功）。

## 六、预期结果

接口应返回参数校验失败，提示"请输入 auths 字段"或"auth_ids 不能为空"。

---

## 七、根因分析

### 1. 现象分析
- 接口正常接收参数，`group_id: 2` 合法，`auth_ids: []` 为合法 JSON 数组（只是长度为 0）
- API 层和 DAO 层均未对 `auth_ids` 做非空校验——空数组直接传入，DAO 层遍历空数组无任何操作后返回成功

### 2. 关键代码
- [app/api/cms/auth.py](app/api/cms/auth.py) — `append_auths()` 方法
- [app/dao/auth.py](app/dao/auth.py) — 追加权限逻辑

### 3. 根因结论

**`FieldList` + `DataRequired` 的组合无法校验空数组。** `FieldList` 的 `DataRequired` 检验的是每个元素的必填性，而非列表本身的非空性——当 `auth_ids: []` 传入时，`FieldList` 遍历 0 次，内层 `DataRequired` validator 从未执行。需要在 `FieldList` 上增加 `min_entries=1` 参数。

**关键代码定位**：
- `app/validators/forms.py:238-246`：`auth_ids = FieldList(IntegerField(validators=[DataRequired(...)]))` —— 只校验元素必填，不校验列表非空
- `app/dao/auth.py:22`：`for id in auth_ids` —— 空数组直接跳过，无操作返回成功

---

## 八、修复方案

### 当前采取的修复策略
- 在 `FieldList` 上增加 `min_entries=1` 参数：`FieldList(IntegerField(...), min_entries=1, message='auth_ids 不能为空')`

### 后续推荐优化方向
- 项目级别统一检查所有 `FieldList` 是否都需要 `min_entries` 约束

## 十五、结论

该问题属于**参数校验缺失**。`auth_ids` 未做非空校验，空数组穿透到业务层后无操作却返回成功。增加 Validator 最小长度校验即可修复。
