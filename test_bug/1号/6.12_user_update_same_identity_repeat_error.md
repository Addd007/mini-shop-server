# Bug Report: 更新自身资料时原用户名/手机号/邮箱被误判为已使用并可能返回服务器异常

**Bug ID**: BUG-USER-UPDATE-SAME-IDENTITY-001  
**标题**: `PUT /v1/user` 更新自身资料时，用户名/手机号/邮箱与原值相同被误判为已使用，修复过程中还触发唯一索引服务器异常  
**模块**: 用户管理 / 更新自身资料  
**严重级别**: 中  
**优先级**: P1  
**状态**: 已修复  
**发现日期**: 2026-06-12  
**提交人**: 测试团队 1号

---

## 一、问题概述

调用更新自身资料接口 `PUT /v1/user` 时，如果请求中的 `username`、`mobile`、`email` 与当前用户原有值相同，接口返回“已被使用”。

该行为不符合预期。当前用户更新自己的资料时，如果某个身份标识没有变化，应允许通过，不应被判定为重复。

在修复过程中，曾出现另一个问题：当同时更新多个身份字段时，服务端返回内部错误：

```json
{
  "error_code": 1007,
  "msg": "The server encountered an internal error and was unable to complete your request. Either the server is overloaded or there is an error in the application.",
  "request_url": "PUT /v1/user"
}
```

服务端日志显示数据库唯一索引冲突：

```text
pymysql.err.IntegrityError: (1062, "Duplicate entry 'user' for key 'identity.identifier'")
```

## 六、预期结果

### 当前用户提交原有身份标识

如果 `username`、`mobile`、`email` 属于当前用户当前身份类型，应允许更新成功。

例如当前用户原用户名为 `user`，请求中仍传：

```json
{
  "username": "user"
}
```

应返回更新成功。

### 身份标识被其他用户占用

如果请求中的 `username`、`mobile`、`email` 被其他用户占用，应返回对应重复提示。

例如：

```json
{
  "username": "admin"
}
```

应返回：

```json
{
  "error_code": 10110,
  "msg": "该用户名已被使用，请重新输入新的用户名",
  "request_url": "PUT /v1/user"
}
```

不应返回服务器端异常。

---

## 七、根因分析

### 1. 原始问题根因

修复前，`UserDao.update_user` 中使用 `Identity.abort_repeat(identifier=...)` 判断重复：

```python
for item in identity_infos:
    Identity.abort_repeat(identifier=item['identifier'], msg=item['msg'])
    IdentityDao.update_identity(
        commit=False, user_id=uid, identifier=item['identifier'], credential=credential, type=item['type']
    )
```

该逻辑只判断标识是否存在，没有排除当前用户自己的身份记录。

因此：

- 当前用户原用户名就是 `user`
- 请求更新 `username=user`
- 数据库中能查到 `identifier=user`
- 系统误判为该用户名已被使用

手机号、邮箱同理。

### 2. 修复过程中服务器异常根因

初版修复逻辑在循环中边校验边更新：

```python
for item in identity_infos:
    existed_identity = Identity.get(identifier=item['identifier'])
    if existed_identity and (existed_identity.user_id != uid or existed_identity.type != item['type']):
        raise RepeatException(msg=item['msg'])
    IdentityDao.update_identity(...)
```

当同一次请求中同时更新多个身份字段时，前一个字段更新会产生待 flush 的 SQL；下一轮查询 `Identity.get(...)` 时会触发 SQLAlchemy 自动 flush，导致数据库唯一索引提前检查并抛出 `IntegrityError`。

因此接口返回服务器端异常。

### 3. 根因结论

问题根因包括：

1. 重复校验未排除当前用户当前身份类型。
2. 初版修复中在同一循环内混合查询和更新，触发 SQLAlchemy 自动 flush，导致唯一索引冲突提前暴露为服务器异常。

---

## 八、修复方案

### 当前采取的修复策略

采用“两阶段处理”：

1. 先完整校验所有待更新的身份标识。
2. 全部校验通过后，再统一执行更新。

判断规则：

- 如果标识不存在：允许更新。
- 如果标识属于当前用户当前身份类型：允许更新。
- 如果标识属于其他用户，或属于当前用户其他身份类型：视为重复，返回“已被使用”。

修复后关键逻辑：

```python
for item in identity_infos:
    current_identity = db.session.query(Identity).filter(
        Identity.user_id == uid,
        Identity.type == item['type'],
        Identity.delete_time == None
    ).first()
    existed_identity = db.session.query(Identity).filter(
        Identity.identifier == item['identifier']
    ).first()
    if existed_identity and (not current_identity or existed_identity.id != current_identity.id):
        raise RepeatException(msg=item['msg'])
    item['current_identity'] = current_identity

for item in identity_infos:
    current_identity = item['current_identity']
    if current_identity:
        current_identity.update(commit=False, identifier=item['identifier'], credential=credential)
    else:
        Identity.create(commit=False, user_id=uid, type=item['type'],
                        identifier=item['identifier'], credential=credential)
```

## 九、修复结果

当前问题已修复。

修复后：

- 当前用户提交原用户名、原手机号、原邮箱，接口返回更新成功。
- 当前用户提交其他用户已占用的用户名、手机号、邮箱，接口返回对应“已被使用”。
- 同时更新多个身份字段时，不再触发唯一索引服务器异常。

---

## 十、建议

1. 为 `PUT /v1/user` 补充当前用户提交原用户名、原手机号、原邮箱的用例。
2. 补充用户名、手机号、邮箱分别被其他用户占用的重复校验用例。
3. 补充同时更新多个身份字段的用例，避免再次出现自动 flush 导致的唯一索引异常。
4. 对其他更新接口中使用 `abort_repeat` 的场景进行排查，确认是否需要排除当前记录。
5. 全局异常处理中的 `IntegrityError` 兼容逻辑也建议排查，避免异常处理自身再次抛错。
