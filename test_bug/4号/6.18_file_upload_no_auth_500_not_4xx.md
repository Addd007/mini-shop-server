# Bug Report: 无 Token 上传文件返回 500 而非 4xx 认证错误

**Bug ID**: BUG-FILE-AUTH-500-001  
**标题**: `POST /v1/file` 无 Token 上传文件时返回 500 服务器端异常，而非 401 未认证  
**模块**: 文件管理 / 认证鉴权  
**严重级别**: 中  
**优先级**: P1  
**状态**: 已定位  
**发现日期**: 2026-06-18  
**提交人**: 测试团队 4号

---

## 一、问题概述

TC-FILE-010 测试"无 Token 上传文件"场景，期望返回 4xx（如 401 未认证），但实际返回了 500 服务器端异常。这表明文件上传接口的认证拦截逻辑存在异常处理缺陷，未认证请求没有被正确识别和拦截，而是在后续处理中抛出了未捕获的异常。

---

## 二、影响范围

### 受影响功能
- 文件上传认证鉴权
- 未认证请求的错误提示

### 受影响接口
- `POST /v1/file`

### 业务影响
- 未认证用户上传文件时收到"服务器端异常"而非"请先登录"
- 前端无法给用户准确的提示
- 服务端异常统计被认证失败污染
- 认证拦截逻辑存在漏洞

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地开发环境
- 服务地址：`http://127.0.0.1:5000`
- 测试文件：`tests/api/4号/test_file_cases.py`

---

## 四、复现步骤

### 步骤 1：不带 Token 发送上传请求

```text
POST /v1/file
Content-Type: multipart/form-data
（无 Authorization 头）

file: test.png
```

### 步骤 2：观察返回

```json
{
  "error_code": 999,
  "msg": "服务器端异常",
  "request_url": "POST /v1/file"
}
```

---

## 五、实际结果

返回 500 + `error_code: 999`，而非 401 认证失败。

---

## 六、预期结果

应返回 401，提示"未认证"或"Token 缺失"。

---

## 七、根因分析

### 1. 现象分析

认证装饰器（`@login_required` 或类似）可能在检测到无 Token 后抛出了异常，但该异常未被正确转换为 401 响应，而是被全局异常处理器捕获为 500。

### 2. 关键代码

待排查：
- `app/api/v1/file.py` — 文件上传视图的认证装饰器
- `app/core/token_auth.py` — Token 认证逻辑
- `app/libs/error.py` — 全局异常处理

### 3. 根因结论

认证拦截层抛出的异常类型未被全局异常处理器正确映射为 401，而是被当作未预期的服务器异常处理。

---

## 八、修复方案

### 推荐修复

确保认证装饰器在 Token 缺失/无效时抛出明确的认证异常（如 `AuthException`），并在全局异常处理器中将该异常映射为 401 状态码。

### 后续推荐
- 对所有需要认证的接口补充无 Token 场景的异常测试
- 统一认证失败的异常类型和错误码

---

## 十、建议

1. 认证装饰器应抛出专用异常类型，而非通用异常
2. 全局异常处理器应为认证异常返回 401，为授权异常返回 403
3. 为所有受保护接口补充无 Token 场景的自动化测试

## 十三、结论

该问题属于认证拦截异常处理缺陷，无 Token 请求上传文件时返回 500 而非 401。这既影响用户体验（错误提示不准确），也可能掩盖认证逻辑中的真实问题。建议修复认证异常的类型映射。
