# Bug Report: `verified=0` 的账号仍可正常登录

**Bug ID**: BUG-AUTH-002  
**标题**: `identity.verified = 0` 的账号仍可通过登录接口获取 token  
**模块**: 认证鉴权 / 登录校验  
**严重级别**: 中  
**优先级**: P1  
**状态**: 待修复  
**发现日期**: 2026-06-10  
**提交人**: 测试团队 1号

---

## 一、问题概述

在登录接口 `POST /v1/token` 中，当用户身份记录 `identity.verified = 0` 时，账号仍然可以正常完成登录并获取 token，未被系统拦截。

这说明登录流程中未对 `verified` 状态做有效校验，导致“未验证账号”也可进入系统。

---

## 二、影响范围

### 受影响功能
- 用户登录校验
- 账号状态控制
- 鉴权入口安全性

### 受影响接口
- `POST /v1/token`
- 依赖登录态的全部受保护接口

### 业务影响
- 未验证账号绕过状态限制直接登录
- 账号状态字段失去控制作用
- 可能影响后续权限控制与审计可靠性

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地开发环境
- 服务地址：`http://127.0.0.1:5000`
- 数据库：`zerd`
- 测试数据：`zerd_test.sql`
- 测试工具：Swagger / Postman / 手工请求

---

## 四、复现步骤

### 步骤 1：确认账号身份记录
将某个账号的 `identity.verified` 设置为 `0`，例如：

```sql
UPDATE identity SET verified = 0 WHERE identifier = 'admin' AND type = 100;
```

### 步骤 2：调用登录接口
请求示例：

```json
{
  "account": "admin",
  "secret": "admin123456",
  "type": 100
}
```

### 步骤 3：观察登录结果
接口仍然成功返回 token，例如：

```json
{
  "data": {
    "token": "eyJ1aWQiOjEsInR5cGUiOjEwMCwic2NvcGUiOiLotoXnuqfnrqHnkIblkZgifQ.ail5Vw.DrNC8DOnKcffjorYaZs_eejRJUU"
  },
  "error_code": 0,
  "msg": "成功"
}
```

---

## 五、实际结果

`identity.verified = 0` 的账号仍可正常登录并获取 token，没有被拒绝。

---

## 六、预期结果

当账号处于未验证状态（`verified = 0`）时，系统应拒绝登录，并返回明确错误信息，例如：

- `账号未验证`
- `账号未激活`
- `账号状态异常，请联系管理员`

不应签发 token。

---

## 七、根因分析

初步判断，登录校验逻辑中未对 `identity.verified` 字段进行状态判断。

### 当前登录流程
- 先查找 `Identity`
- 再校验密码
- 再查找 `User`
- 成功后签发 token

### 缺失点
未见如下拦截逻辑：

```python
if not identity.verified:
    raise AuthFailed(msg='账号未验证')
```

因此，未验证账号仍可正常完成登录流程。

---

## 八、建议修复方案

在用户名 / 邮箱 / 手机号登录逻辑中，增加 `verified` 状态判断：

```python
if not identity.verified:
    raise AuthFailed(msg='账号未验证')
```

如业务上 `verified` 表示的是“启用状态”或“激活状态”，则应根据业务语义改为相应错误提示。

---

## 九、修复建议验证点

修复后应验证以下场景：

1. `verified = 1` 的账号可正常登录
2. `verified = 0` 的账号无法登录
3. 返回错误信息明确且符合业务规范
4. 登录后 token 校验与后续受保护接口访问不受影响
