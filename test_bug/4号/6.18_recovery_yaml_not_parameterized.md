# Bug Report: recovery_cases.yaml 定义了 7 个用例但全部未通过参数化使用

**Bug ID**: BUG-RECOV-YAML-UNUSED-001  
**标题**: `recovery_cases.yaml` 中 7 个用例全部通过独立手写函数实现，YAML 中的 `expected.status_code` 等定义未被使用，且部分期望值与代码断言不一致  
**模块**: 异常恢复 / 自动化测试  
**严重级别**: 中  
**优先级**: P2  
**状态**: 已定位  
**发现日期**: 2026-06-18  
**提交人**: 测试团队 4号

---

## 一、问题概述

4号异常恢复测试中，`recovery_cases.yaml` 定义了 7 个用例（TC-RECOV-001 ~ TC-RECOV-007），每个用例都有完整的 `params`、`expected` 等字段。但 Python 测试代码中所有 7 个测试函数都是独立手写函数，YAML 用例数据被加载到 `RECOVERY_CASES` 列表后从未被参数化使用。此外，部分 YAML 中的期望值与代码断言存在不一致。

## 七、根因分析

### 1. 现象分析

recovery 测试采用独立函数模式，而其他模块（file、log、deploy、env、perf、swagger）都采用 YAML 参数化模式，设计不一致。

### 2. 关键代码

```python
# tests/api/4号/test_recovery_cases.py
RECOVERY_CASES = [c for c in load_cases("recovery_cases.yaml") if c.get("tag") == "recovery"]
# 从未被使用

def test_health_check(auth_client):
    resp = auth_client.request("GET", "/health")
    ...
```

### 3. 根因结论

Recovery 测试模块的设计与其他模块不一致，YAML 数据成了冗余定义。

---

## 八、修复方案

### 推荐修复

将 recovery 测试改为参数化模式，与其他模块保持一致：

```python
@pytest.mark.parametrize("case", RECOVERY_CASES, ids=[c["id"] for c in RECOVERY_CASES])
def test_recovery(auth_client, case):
    resp = _execute_case(auth_client, case)
    expected_status = case["expected"]["status_code"]
    if isinstance(expected_status, list):
        assert resp.status_code in expected_status
    else:
        assert resp.status_code == expected_status
```

同时将 YAML 中的 `expected.status_code` 更新为与当前代码断言一致的范围值（使用列表格式）。

### 后续推荐
- 统一所有测试模块的实现模式（全部参数化或全部独立函数）
- 将 YAML 作为唯一的期望值来源，代码不再硬编码断言范围

## 十、建议
