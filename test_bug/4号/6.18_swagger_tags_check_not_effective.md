# Bug Report: Swagger 标签完整性验证未生效，EXPECTED_SWAGGER_MODULES 定义但从未使用

**Bug ID**: BUG-SWAGGER-TAGS-001  
**标题**: `check_tags` 仅验证标签非空，未将实际标签与 `EXPECTED_SWAGGER_MODULES` 列表对比，TC-SWAG-005 形同虚设  
**模块**: Swagger 文档 / 自动化测试  
**严重级别**: 中  
**优先级**: P2  
**状态**: 已定位  
**发现日期**: 2026-06-18  
**提交人**: 测试团队 4号

---

## 一、问题概述

4号 Swagger 测试中，`test_swagger_cases.py` 文件顶部定义了 `EXPECTED_SWAGGER_MODULES` 常量（包含 25 个预期模块标签），但在 `check_tags` 函数中仅验证了 `len(tag_names) > 0`（标签列表非空），**从未将实际标签与期望列表做对比**。这导致 TC-SWAG-005（验证标签完整性）即使 Swagger 文档缺少关键模块标签也能通过，是一个无效测试。

---

## 二、影响范围

### 受影响功能
- Swagger 文档完整性校验
- API 模块标签验证
- 自动化测试有效性

### 受影响接口
- `GET /apispec_1.json`（Swagger JSON 规范）

### 业务影响
- 如果 Swagger 文档缺少某个模块（如 file、log、deploy），测试仍会通过
- TC-SWAG-005 无法发现文档标签缺失问题
- 测试提供虚假的安全感，掩盖真实缺陷

### 1. 现象分析

`EXPECTED_SWAGGER_MODULES` 常量已定义但未被任何断言引用，属于未完成的测试逻辑。

### 2. 关键代码

```python

EXPECTED_SWAGGER_MODULES = [...]  # 定义但未使用

    assert len(tag_names) > 0, "Swagger tags 为空"
    # 缺少与 EXPECTED_SWAGGER_MODULES 的对比
```

### 3. 根因结论

标签完整性校验逻辑未完成，`EXPECTED_SWAGGER_MODULES` 是预留但未实现的验证数据。

## 八、修复方案

### 推荐修复

```python
def check_tags(resp, case):
    body = resp.json()
    tag_names = [tag["name"] for tag in body.get("tags", [])]
    assert len(tag_names) > 0, "Swagger tags 为空"
    
    # 验证所有预期模块标签存在
    missing = [m for m in EXPECTED_SWAGGER_MODULES if m not in tag_names]
    assert not missing, f"Swagger 缺少以下模块标签: {missing}"
```

### 后续推荐
- 如果某些模块标签是可选的，将 `EXPECTED_SWAGGER_MODULES` 分为必选和可选两类
- 当服务新增模块时，同步更新期望标签列表
