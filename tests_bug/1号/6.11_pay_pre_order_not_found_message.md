# Bug Report: 预支付接口订单不存在时返回通用错误提示不明确

**Bug ID**: BUG-PAY-ORDER-NOTFOUND-001  
**标题**: `POST /v1/pay/pre_order` 查询不存在订单时返回“订单类通用错误”，无法明确说明订单不存在  
**模块**: 订单系统 / 支付 / 预支付校验  
**严重级别**: 低  
**优先级**: P2  
**状态**: 已修复  
**发现日期**: 2026-06-11  
**提交人**: 测试团队 1号

---

## 一、问题概述

调用预支付接口 `POST /v1/pay/pre_order` 时，如果请求中的订单 ID 不存在，接口返回 `订单类通用错误`。

该错误虽然能表示请求失败，但没有明确说明失败原因是“订单不存在”，导致测试人员和前端调用方难以快速判断是订单 ID 传错、订单被删除，还是其他订单业务异常。

---

## 二、影响范围

### 受影响功能
- 预支付订单校验
- 订单不存在场景提示
- 支付链路异常处理
- 接口测试与问题定位

### 受影响接口 / 页面
- `POST /v1/pay/pre_order`

### 业务影响
- 错误提示不明确，增加排查成本
- 前端无法根据错误信息给用户展示准确提示
- 测试用例中订单不存在场景难以判断实际失败原因
- 不影响正常订单支付主流程，但影响异常场景可读性

## 四、复现步骤

### 步骤 1：准备登录用户

使用有效用户账号登录，获取 token。

### 步骤 2：确认订单 ID 不存在

确认数据库 `order` 表中不存在目标订单 ID，例如：

```text
id = 999999
```

### 步骤 3：调用预支付接口

请求接口：

```text
POST /v1/pay/pre_order
```

请求 Body：

```json
{
  "id": 999999
}
```

### 步骤 4：观察接口返回

接口返回订单通用错误，而不是明确的订单不存在提示。

## 五、实际结果

修复前接口返回：

```json
{
  "error_code": 50000,
  "msg": "订单类通用错误",
  "request_url": "POST /v1/pay/pre_order"
}
```

该提示无法明确说明订单不存在。

---

## 六、预期结果

当订单 ID 不存在时，接口应返回明确业务错误，例如：

```json
{
  "error_code": 50010,
  "msg": "订单不存在",
  "request_url": "POST /v1/pay/pre_order"
}
```

或者使用项目已有的订单不存在错误信息：

```json
{
  "error_code": 50010,
  "msg": "没有找到相关订单",
  "request_url": "POST /v1/pay/pre_order"
}
```

---

## 七、根因分析

### 1. 现象分析

该问题不是订单状态错误或用户不匹配导致的，因为订单不存在时，在进入订单状态校验和用户匹配校验之前就已经查询失败。

### 2. 关键代码 / 关键逻辑

修复前，预支付服务查询订单时使用了默认 `OrderException`：

```python
order = Order.query.filter_by(id=self.order_id) \
    .first_or_404(e=OrderException)
```

`OrderException` 的默认文案是：

```python
class OrderException(APIException):
    code = 404
    error_code = 50000
    msg = '订单类通用错误'
```

因此，当订单不存在时，接口只能返回通用错误，而无法说明具体原因。

### 3. 根因结论

问题根因是预支付订单查询失败时使用了默认订单异常类，没有传入具体的错误信息和错误码，导致订单不存在场景返回“订单类通用错误”。

---

## 八、修复方案

### 当前采取的修复策略

已将订单不存在场景的异常提示改为明确的业务错误。

修复前：

```python
order = Order.query.filter_by(id=self.order_id) \
    .first_or_404(e=OrderException)
```

修复后：

```python
order = Order.query.filter_by(id=self.order_id) \
    .first_or_404(e=OrderException(msg='订单不存在', error_code=50010))
```

### 后续推荐优化方向
- 统一订单不存在场景的错误码和错误文案。
- 优先复用已有 `OrderNotFound` 异常类，避免各处文案不一致。
- 对订单相关接口补充不存在 ID 的边界测试。

---

## 九、修复结果

当前问题已修复。

修复后，当传入不存在的订单 ID 时，接口应返回：

```json
{
  "error_code": 50010,
  "msg": "订单不存在",
  "request_url": "POST /v1/pay/pre_order"
}
```

该提示比原来的“订单类通用错误”更明确，有助于前端展示和测试定位。

---

## 十、建议

1. 将订单不存在场景加入 `TC-ORDER-004` 的异常分支测试。  
2. 对 `GET /v1/order/{id}`、`POST /v1/pay/pre_order` 等订单查询类接口统一错误提示。  
3. 优先使用 `OrderNotFound` 等语义明确的异常类，减少通用异常滥用。  
4. 在接口文档中明确 `id` 为订单 ID，而不是商品 ID 或订单号。
