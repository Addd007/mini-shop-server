# Bug Report: SQL 注入测试 URL 含特殊字符未做编码

**Bug ID**: BUG-RECOV-SQL-INJECT-URL-001  
**标题**: `test_sql_injection_attempt` 请求路径包含空格和特殊字符但未做 URL 编码，可能导致请求在客户端或服务端被拒绝  
**模块**: 异常恢复 / 安全测试 / 自动化测试  
**严重级别**: 低  
**优先级**: P2  
**状态**: 已定位  
**发现日期**: 2026-06-18  
**提交人**: 测试团队 4号

---

## 一、问题概述

4号异常恢复测试中，TC-RECOV-006（SQL 注入尝试）构造的请求路径为：

```
/cms/file/name/'; DROP TABLE file; --
```

该路径包含空格、单引号和分号等特殊字符。`ApiClient.request()` 直接将路径拼接到 URL 中，未做 URL 编码。这可能导致：
- HTTP 客户端因 URL 格式非法而拒绝发送请求
- 服务端在 URL 解析层面就拒绝请求（返回 400），无法到达业务层
- 测试无法真正验证服务端对 SQL 注入的防护能力

---

## 二、影响范围

### 受影响功能
- SQL 注入安全测试
- 路径参数特殊字符处理验证

### 受影响接口
- `GET /cms/file/name/{name}`

### 业务影响
- SQL 注入测试可能因 URL 格式问题被提前拦截，无法验证业务层防护
- 如果客户端自动编码了路径，测试结果依赖库的编码行为，不可控
- 无法区分"服务端安全拦截"和"请求格式错误"

- 项目：`mini-shop-server`
- 环境：本地开发环境
- 服务地址：`http://127.0.0.1:5000`
- 测试文件：`tests/api/4号/test_recovery_cases.py`

## 四、复现步骤

### 步骤 1：查看 TC-RECOV-006 请求构造

```python
def test_sql_injection_attempt(auth_client):
    path = "/cms/file/name/'; DROP TABLE file; --"
    resp = auth_client.request("GET", path)
    assert resp.status_code in (200, 404)
```

### 步骤 2：查看 `ApiClient.request()` 实现

```python
def request(self, method, path, **kwargs):
    url = f"{self.base_url}{path}"  # 直接拼接，未编码
    return self.session.request(method, url, **kwargs)
```

### 步骤 3：分析

路径中的空格和特殊字符直接拼接到 URL 中，`requests` 库可能会自动进行部分编码，但行为不可控。

---

## 五、实际结果

请求 URL 包含未编码的特殊字符，实际发出的请求取决于 `requests` 库的自动编码行为：
- 空格可能被编码为 `%20` 或 `+`
- 分号、单引号可能保持原样
- 服务端可能因 URL 非法而返回 400

---

## 六、预期结果

SQL 注入测试应对路径参数进行明确的 URL 编码，确保特殊字符正确传输到服务端，从而验证业务层的 SQL 注入防护能力。

```python
from urllib.parse import quote
sql_payload = "'; DROP TABLE file; --"
encoded_payload = quote(sql_payload, safe='')
path = f"/cms/file/name/{encoded_payload}"
```

---

## 七、根因分析

### 1. 现象分析

`ApiClient.request()` 直接拼接 URL，未对路径中的特殊字符进行编码处理。

### 2. 关键代码

```python
# tests/api/common/http_client.py
def request(self, method, path, **kwargs):
    url = f"{self.base_url}{path}"  # 未编码
    return self.session.request(method, url, **kwargs)
```

### 3. 根因结论

HTTP 客户端缺少 URL 编码处理，导致包含特殊字符的测试路径可能无法正确传输。

---

## 八、修复方案

### 推荐修复

在 `ApiClient.request()` 中增加路径编码：

```python
from urllib.parse import quote

def request(self, method, path, **kwargs):
    # 对路径中的特殊字符进行编码，但保留 /
    parts = path.split('/')
    encoded_parts = [quote(p, safe='') for p in parts]
    encoded_path = '/'.join(encoded_parts)
    url = f"{self.base_url}{encoded_path}"
    return self.session.request(method, url, **kwargs)
```

或在测试用例层面进行编码：

```python
from urllib.parse import quote

def test_sql_injection_attempt(auth_client):
    sql_payload = "'; DROP TABLE file; --"
    path = f"/cms/file/name/{quote(sql_payload)}"
    resp = auth_client.request("GET", path)
    assert resp.status_code in (200, 404)
```

### 后续推荐
- 将 URL 编码作为 `ApiClient` 的内置功能，对所有路径参数自动编码
- 为 XSS、路径遍历等安全测试增加类似的编码处理
- 补充 URL 编码的单元测试

## 十、建议
