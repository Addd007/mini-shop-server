**优先级**: P1  
**状态**: 🟡 降级为建议（开发环境可接受）

## 一、更新说明（2026-06-19）

### 之前的 Bug（测试代码缺陷）

历史上 `check_no_server_header` 和 `check_debug_mode` 两个函数**只有 allure 记录，没有 assert 断言**，导致即使服务端存在敏感信息泄露也无法被测试发现。

### 当前状态：测试代码已修复

当前测试代码中 `check_no_server_header` 已有有效断言：

```python
for header, val in found_sensitive.items():
    assert not val or len(val.split("/")) < 2, (
        f"[{case['id']}] 敏感头 {header} 暴露了版本信息: {val}"
    )
```

### 新发现：真实安全缺陷

TC-ENV-005 **正确 FAILED**，因为服务端在响应头中暴露了详细版本信息：

```
AssertionError: [TC-ENV-005] 敏感头 Server 暴露了版本信息: 
  Werkzeug/2.0.3 Python/3.9.13
```

---

## 二、安全风险

| 响应头 | 泄露内容 | 风险 |
|--------|----------|------|
| `Server` | `Werkzeug/2.0.3 Python/3.9.13` | 🔴 攻击者可利用已知版本的 CVE |
| `X-Powered-By` | 未发现 | ✅ |

泄露详细版本信息（Werkzeug 版本、Python 版本）会显著增加攻击面：
- 攻击者可直接针对 `Werkzeug 2.0.3` 已知漏洞发起攻击
- Python 3.9.13 暴露运行环境信息，辅助信息收集

---

## 三、修复方案

### 方案一：Flask 配置（推荐）

```python
# app/__init__.py 或 config
app.config['SERVER_NAME'] = None  # 不暴露 Server 头
```

或在创建 app 后手动设置：
```python
from flask import Flask
app = Flask(__name__)

# 隐藏 Server 头
@app.after_request
def remove_server_header(response):
    response.headers.pop('Server', None)
    response.headers.pop('X-Powered-By', None)
    return response
```

### 方案二：生产环境反向代理

通过 Nginx 反向代理覆盖 `Server` 头为通用值（如 `nginx`）。
