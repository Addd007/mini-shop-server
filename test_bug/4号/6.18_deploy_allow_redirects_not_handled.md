# Bug Report: TC-DEPLOY-006 未处理 `allow_redirects` 字段，与 TC-DEPLOY-001 行为完全一致

**Bug ID**: BUG-DEPLOY-REDIRECT-001  
**标题**: `test_deploy` 中 TC-DEPLOY-006 的 `allow_redirects: true` 字段未被代码处理，导致两个用例无法区分  
**模块**: 部署配置 / 自动化测试  
**严重级别**: 低  
**优先级**: P2  
**状态**: 已定位  
**发现日期**: 2026-06-18  
**提交人**: 测试团队 4号

---

## 一、问题概述

部署配置测试中，TC-DEPLOY-001 和 TC-DEPLOY-006 都访问 `GET /`，但 TC-DEPLOY-006 在 YAML 中额外设置了 `allow_redirects: true`，意图测试根路径的重定向行为。然而 Python 测试代码 `_execute_case()` 和 `ApiClient.request()` 均未处理 `allow_redirects` 字段，导致两个用例的实际请求完全相同，无法区分。

---

## 二、影响范围

### 受影响功能
- 部署配置验证
- 根路径重定向行为测试

### 受影响接口
- `GET /`（根路径）

### 业务影响
- TC-DEPLOY-006 无法达成其设计目的
- 如果根路径存在重定向行为，该测试无法区分和验证
- 两个用例冗余，浪费测试资源

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地开发环境
- 服务地址：`http://127.0.0.1:5000`
- 测试文件：`tests/api/4号/test_deploy_cases.py`

---

## 四、复现步骤

### 步骤 1：查看 YAML 用例定义

```yaml
- id: TC-DEPLOY-001
  tag: deploy
  desc: 服务根路径可访问
  params:
    method: GET
    path: /
  expected:
    status_code: 200

- id: TC-DEPLOY-006
  tag: deploy
  desc: 根路径默认路由可正常重定向
  params:
    method: GET
    path: /
    allow_redirects: true
  expected:
    status_code: 200
```

### 步骤 2：查看 `_execute_case()` 和 `ApiClient.request()`

代码中未出现对 `allow_redirects` 的处理逻辑，`requests.Session.request()` 默认自动跟随重定向。

### 步骤 3：运行两个用例

两个用例发出的 HTTP 请求完全一致，得到相同的响应。

---

## 五、实际结果

TC-DEPLOY-006 与 TC-DEPLOY-001 行为完全相同，`allow_redirects` 字段被忽略。

---

## 六、预期结果

TC-DEPLOY-006 应能控制是否跟随重定向，例如先发送 `allow_redirects=False` 的请求验证返回 3xx，再验证重定向目标。

---

## 七、根因分析

### 1. 现象分析

YAML 中定义了 `allow_redirects` 字段，但测试代码未消费该字段。

### 2. 关键代码

```python
# ApiClient.request() 和 _execute_case() 均未处理 allow_redirects
resp = client.request(method, url, **kwargs)
```

### 3. 根因结论

YAML 驱动测试框架中缺少对 `allow_redirects` 参数的支持。

---

## 八、修复方案

### 推荐修复

在 `_execute_case()` 中增加对 `allow_redirects` 的处理：

```python
allow_redirects = case.get("allow_redirects")
if allow_redirects is not None:
    kwargs["allow_redirects"] = allow_redirects
```

或者在 `ApiClient.request()` 中支持该参数透传。

### 后续推荐
- 完善重定向测试：先验证 302 状态码，再验证 Location 头指向正确路径
- 将 `allow_redirects` 作为通用参数加入测试框架
