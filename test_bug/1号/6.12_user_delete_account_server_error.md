# Bug Report: 注销账号返回服务器端异常

**Bug ID**: BUG-USER-DELETE-001  
**标题**: 注销当前账号接口返回 999 服务器端异常  
**模块**: 用户管理  
**严重级别**: 高  
**优先级**: P1  
**状态**: 已修复  
**发现日期**: 2026-06-12  
**提交人**: 1号

---

## 一、问题概述

调用 `DELETE /v1/user` 注销当前账号接口时，系统返回 `999 服务器端异常`，导致用户无法正常注销账号。

---

## 二、影响范围

### 受影响功能
- 用户账号注销

### 受影响接口 / 页面
- `DELETE /v1/user`

### 业务影响
- 用户无法注销自己的账号
- 影响用户数据隐私权相关功能

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：`本地开发`
- 服务地址：`http://127.0.0.1:5000`
- 测试接口：`DELETE /v1/user`

---

## 四、复现步骤

### 步骤 1：登录获取 Token
使用有效账号登录，获取 access_token

### 步骤 2：调用注销接口
发送 DELETE 请求到 `/v1/user`，Header 携带 `Authorization: Bearer <token>`

### 步骤 3：观察结果
接口返回 999 服务器端异常

---

## 五、实际结果

接口返回如下错误：

```json
{
    "error_code": 999,
    "msg": "服务器端异常",
    "request_url": "DELETE /v1/user"
}
```

---

## 六、预期结果

接口应正常返回注销成功的响应，用户账号及相关身份信息被软删除。

---

## 七、根因分析

### 1. 现象分析
返回 999 错误码表示服务端发生未捕获的异常，需要检查后端代码逻辑。

### 2. 关键代码 / 关键逻辑

问题位于 `app/dao/user.py` 的 `delete_user` 方法：

**原代码：**

```python
@staticmethod
def delete_user(uid):
    user = User.query.filter_by(id=uid).first_or_404()
    with db.auto_commit():
        Identity.query.filter_by(user_id=user.id).delete(commit=False)
        user.delete(commit=False)
```

`Identity.query.filter_by(user_id=user.id).delete(commit=False)` 调用的是 SQLAlchemy Query 对象的 `delete()` 方法，这是一个批量删除操作，**不接受 `commit` 参数**。

项目中 `commit=False` 是自定义 Model 实例方法 `delete(commit=False)` 的参数，而不是 Query 的 `delete()` 方法参数。将 `commit=False` 传递给 Query 的 `delete()` 会导致 `TypeError` 异常。

### 3. 根因结论
混淆了 SQLAlchemy Query 的 `delete()` 批量删除方法与自定义 Model 实例的 `delete(commit)` 软删除方法，导致传参错误引发异常。

---

## 八、修复方案

### 当前采取的修复策略
先查询出所有关联的 Identity 记录，再逐个调用模型实例的 `delete(commit=False)` 方法进行软删除：

```python
@staticmethod
def delete_user(uid):
    user = User.query.filter_by(id=uid).first_or_404()
    identity_list = Identity.query.filter_by(user_id=user.id).all()
    with db.auto_commit():
        for identity in identity_list:
            identity.delete(commit=False)
        user.delete(commit=False)
```

### 后续推荐优化方向
- 统一 DAO 层删除方法的命名和参数约定，避免混淆
- 增加单元测试覆盖用户注销场景

---

## 九、修复结果

当前问题已修复，`DELETE /v1/user` 接口可正常注销账号，用户及身份信息被正确软删除。
