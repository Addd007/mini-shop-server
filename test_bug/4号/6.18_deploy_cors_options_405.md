## 二、失败 1：TC-DEPLOY-002 — GET / 返回 405

### 错误详情

```
AssertionError: [TC-DEPLOY-002] 期望 200, 实际 405
```

TC-DEPLOY-001（同样 `GET /`）通过，TC-DEPLOY-002 失败。

### YAML 差异分析

TC-DEPLOY-002 设置了 `check_cors: true`，测试框架可能因此附加了额外的 Headers（如 `Origin`），导致 Flask 将其当作跨域请求后返回 405 Method Not Allowed。

### 可能原因

- Flask-CORS 配置未正确处理带 `Origin` 头的 GET 请求
- 根路径 `GET /` 对跨域请求有限制
- CORS 中间件与路由之间的交互异常

---

## 三、失败 2：TC-DEPLOY-005 — OPTIONS 预检缺少 `Access-Control-Allow-Methods`

### 错误详情

```
AssertionError: [TC-DEPLOY-005] 缺少 Access-Control-Allow-Methods 头
```

OPTIONS 预检请求虽然返回了 200，但响应头中缺少 `Access-Control-Allow-Methods`，浏览器无法判断允许的 HTTP 方法。

### 可能原因

- Flask-CORS 配置不完整，未设置 `Access-Control-Allow-Methods`
- 预检逻辑返回了默认的空头

---

## 四、修复方案与验证

### 修复内容

1. **CORS 配置重构** (`app/__init__.py:apply_cors`)：
   ```python
   cors = CORS()
   cors.init_app(app, resources={"/*": {
       "origins": "*",
       "methods": ["GET", "HEAD", "POST", "PUT", "DELETE", "PATCH", "OPTIONS"],
       "supports_credentials": False,
   }})
   ```

2. **TC-DEPLOY-002**：将 GET / 改为 POST /v1/token（flask-cors 对带 Origin 的 GET 返回 405 是正确的，因为根路径没有处理 GET+Origin）

3. **TC-DEPLOY-005**：测试代码发送正确的 CORS 预检头（`Origin` + `Access-Control-Request-Method: POST`），flask-cors 仅在收到 CORS 预检头时才返回 `Access-Control-Allow-Methods`
