# Bug Report: Swagger UI 路径 `GET /apidocs/` 返回 HTML 导致 JSON 解析失败

**Bug ID**: BUG-SWAGGER-UI-HTML-001  
**标题**: TC-SWAG-001 访问 `GET /apidocs/` 返回 Swagger UI HTML 页面，代码尝试 `.json()` 解析导致 `JSONDecodeError`  
**模块**: Swagger 文档 / 测试代码  
**严重级别**: 低  
**优先级**: P2  
**状态**: 已定位  
**发现日期**: 2026-06-18  
**提交人**: 测试团队 4号

---

## 一、问题概述

TC-SWAG-001 测试"Swagger UI 页面可访问"，访问 `GET /apidocs/`，服务端正确返回了 200 和 Swagger UI 的 HTML 页面。但测试代码中 `_execute_case()` 函数对所有响应都尝试 `.json()` 解析，HTML 内容无法被解析为 JSON，抛出 `requests.exceptions.JSONDecodeError: Expecting value: line 1 column 1 (char 0)`。

---

## 二、影响范围

### 受影响功能
- Swagger UI 可访问性测试

### 受影响接口
- `GET /apidocs/`

### 业务影响
- TC-SWAG-001 测试失败（但服务端实际正常）
- 测试代码无法区分"服务异常"和"响应格式不匹配"

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地开发环境
- 服务地址：`http://127.0.0.1:5000`
- 测试文件：`tests/api/4号/test_swagger_cases.py`

---

## 四、复现步骤

### 步骤 1：访问 Swagger UI

```text
GET /apidocs/
```

服务端返回 200，内容是 Swagger UI HTML 页面。

### 步骤 2：测试代码处理

```python
body = resp.json() if resp.text else {}
# HTML 内容 → JSONDecodeError
```

---

## 五、实际结果

`JSONDecodeError: Expecting value: line 1 column 1 (char 0)`

服务端实际返回正常（200 + HTML），但测试代码对 HTML 做了 JSON 解析。

---

## 六、预期结果

TC-SWAG-001 应验证状态码为 200，且响应内容包含 Swagger UI 特征（如 `swagger-ui`），不应对 HTML 响应调用 `.json()`。

---

## 七、根因分析

### 1. 现象分析

`_execute_case()` 函数对所有响应统一调用 `.json()`，没有区分 JSON API 和 HTML 页面的场景。

### 2. 关键代码

```python
# tests/api/4号/test_swagger_cases.py
body = resp.json() if resp.text else {}
```

### 3. 根因结论

测试代码未区分响应格式，对 HTML 页面错误地调用了 JSON 解析。

---

## 八、修复方案

### 推荐修复

在 `_execute_case()` 或 `test_swagger` 中增加 Content-Type 判断：

```python
if "application/json" in resp.headers.get("Content-Type", ""):
    body = resp.json()
else:
    body = resp.text  # HTML 或其他格式
```

或在 TC-SWAG-001 的 YAML 中增加 `is_html: true` 标记，测试代码据此跳过 JSON 解析。

### 后续推荐
- `_execute_case()` 应根据响应 Content-Type 自动选择合适的解析方式
- 为 HTML 页面测试增加专门的断言（如检查是否包含特定字符串）

---

## 十、建议

1. `_execute_case()` 应支持 `Content-Type: text/html` 的响应处理
2. YAML 用例中增加 `response_type: html` 字段标识非 JSON 响应
3. HTML 页面测试应使用字符串匹配断言，而非 JSON 字段断言

## 十三、结论

该问题属于测试代码缺陷，非服务端问题。Swagger UI 正常返回 HTML 页面（200），但测试代码对所有响应做了 JSON 解析导致失败。建议修复 `_execute_case()` 使其能正确处理非 JSON 响应。
