# Bug Report: 登录 token 无法通过 `/v1/token/verify` 校验

**Bug ID**: BUG-TOKEN-VERIFY-001  
**标题**: 登录接口返回的 token 无法被 `/v1/token/verify` 正常解析  
**模块**: 认证鉴权 / Token 校验  
**严重级别**: 高  
**优先级**: P0  
**状态**: 已修复  
**发现日期**: 2026-06-10  
**修复日期**: 2026-06-10  
**提交人**: 测试团队 1号

---

## 一、问题概述

调用登录接口 `POST /v1/token` 成功后，接口可正常返回 `data.token`；但将该 token 原样传入 `POST /v1/token/verify` 后，接口返回 `token失效` 或 `服务器端异常`，无法完成 token 解析校验。

该问题会导致登录后的 token 无法用于后续鉴权流程，影响整个认证链路的可用性。

---

## 二、影响范围

### 受影响功能
- 用户登录后 token 校验
- 受 token 鉴权保护的接口访问
- 登录态解析与权限校验

### 受影响接口
- `POST /v1/token`
- `POST /v1/token/verify`
- 依赖 token 的全部受保护接口

### 业务影响
- 登录后无法完成 token 校验
- 用户无法通过正常登录态访问后续接口
- 核心鉴权链路不可用

---

接口返回：

---

## 五、实际结果

`/v1/token/verify` 无法正确解析登录接口返回的 token，校验失败。

---

## 六、预期结果

登录接口返回的 token 应可被 `/v1/token/verify` 原样解析，返回 token 中的用户信息，例如：

- `uid`
- `scope`
- 相关有效期信息

接口应返回成功，不应报 `token失效` 或服务器异常。

---

## 七、根因分析

经排查，问题原因为**登录 token 的签发逻辑与 token 验证逻辑使用了不同的 serializer 实现**，导致两端 token 规则不一致，无法互相解析。

### 具体表现
- 登录签发 token 使用：`URLSafeTimedSerializer`
- token 校验使用：`TimedJSONWebSignatureSerializer`

两种 serializer 生成和解析的 token 格式不一致，因此即使 token 来自登录接口，也无法被验证接口正确解析。

---

## 八、修复方案

已统一 token 签发与解析逻辑，使登录与验证使用同一套 serializer 和同一套过期规则。

### 修复内容
- 统一 `app/service/login_verify.py` 中的 token 解析逻辑
- 使用与登录签发一致的 serializer
- 修正 `loads()` 的调用方式，避免解析异常

---

## 九、修复结果

修复后验证结果：
- 登录接口返回 token 正常
- `/v1/token/verify` 可正常解析登录返回的 token
- 返回 token 中的用户信息正常
- 无 `token失效` 和服务器异常

---

## 十、建议

1. 将 token 签发与验证逻辑统一抽象，避免后续再次出现实现不一致问题。  
2. 为登录 token 生成与解析补充自动化测试，覆盖：
   - 正常 token 解析
   - 过期 token 解析
   - 非法 token 解析
3. 在接口文档中注明 token 返回格式与验证方式，避免示例与实际实现脱节。
