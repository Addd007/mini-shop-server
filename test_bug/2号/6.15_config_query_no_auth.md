# Bug Report: Config 查询接口未鉴权

**Bug ID**: BUG-CONFIG-AUTH-001  
**标题**: GET `/cms/config/list` 和 `/cms/config/{id}` 等查询接口未要求登录即可访问  
**模块**: 参数配置管理  
**严重级别**: 低  
**优先级**: P2  
**状态**: 已定位  
**发现日期**: 2026-06-15  
**提交人**: 测试团队 2号

---

## 一、问题概述

`GET /cms/config/list` 接口未添加鉴权装饰器，未登录用户可直接访问并获取完整参数配置列表（含 `key`、`value`、`remark` 等字段）。

而新建（`POST`）、更新（`PUT`）、删除（`DELETE`）接口使用了 `@auth.group_required`，说明修改类操作有权限控制，但查询类接口遗漏了鉴权。

---

## 二、影响范围

### 受影响功能
- 参数配置列表查询
- 参数配置详情/按 Key 查询

### 受影响接口
- `GET /cms/config/list`
- `GET /cms/config/{id}`
- `GET /cms/config/key/{key}`

### 业务影响
- 系统参数配置被未授权用户直接获取，可能存在信息泄露风险
- 与其他类似模块（如 dict、notice 列表）的鉴权策略不一致

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地开发环境
- 服务地址：`http://127.0.0.1:5000`

---

## 四、复现步骤

### 步骤 1：不携带 Token 直接访问
```bash
curl -s "http://127.0.0.1:5000/cms/config/list?page=1&size=10"
```

### 步骤 2：观察结果
返回 HTTP 200，正常返回配置列表数据。

## 六、预期结果

未登录时应返回 401 未认证错误，或至少需 `@auth.group_required` 权限。

---

## 七、根因分析

### 1. 现象分析
- 对比源码，`GET /cms/config/list` 等查询接口**缺少** `@auth.group_required` 装饰器
- `POST /cms/config`（新建）有 `@auth.group_required`，但 `GET` 查询接口遗漏

### 2. 关键代码
- [app/api/cms/config.py](app/api/cms/config.py) — 检查各接口的鉴权装饰器

### 3. 根因结论

**Config 查询接口（`/list`、`/{id}`、`/key/{key}`）遗漏了 `@auth.group_required` 装饰器。** 同模块的修改类接口（`POST`、`PUT`、`DELETE`）均有 `@auth.group_required`，仅查询接口遗漏。

**关键代码定位**：
- `app/api/cms/config.py`：查询接口方法缺少 `@auth.group_required`

---

## 八、修复方案

### 当前采取的修复策略
- 为 `GET /cms/config/list`、`GET /cms/config/{id}`、`GET /cms/config/key/{key}` 添加 `@auth.group_required`

### 后续推荐优化方向
- 统一审查所有 CMS 模块的查询接口是否有鉴权遗漏
