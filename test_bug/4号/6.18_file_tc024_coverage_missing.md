# Bug Report: TC-FILE-024 无对应测试函数，下载静态资源 URL 验证缺失

**Bug ID**: BUG-FILE-COVERAGE-024  
**标题**: YAML 中 TC-FILE-024（下载静态资源 URL）属于 `download_verify` 标签但无参数化测试函数覆盖  
**模块**: 文件管理 / 测试覆盖  
**严重级别**: 中  
**优先级**: P2  
**状态**: 已定位  
**发现日期**: 2026-06-18  
**提交人**: 测试团队 4号

---

## 一、问题概述

4号文件测试的 YAML 用例定义了 29 个用例，但 pytest 收集到的测试项只有 27 个（原对话中确认 68 个 YAML 用例仅收集到 66 个，其中 file 模块少了 2 个）。TC-FILE-024 属于 `download_verify` 标签，在 YAML 中有完整定义，但 Python 测试代码中 `test_upload_and_download_integrity` 函数仅标注为 TC-FILE-023，TC-FILE-024 没有任何测试函数覆盖。

---

- 测试覆盖率完整性

- 如果服务端静态资源 URL 生成逻辑有缺陷，不会被自动化测试发现
- 测试覆盖存在盲区

## 六、预期结果

TC-FILE-024 应有独立的测试函数或通过参数化被覆盖，验证上传文件后可以通过静态资源 URL 访问文件。

---

## 七、根因分析

### 1. 现象分析

`DOWNLOAD_VERIFY_CASES` 列表加载了 TC-FILE-023 和 TC-FILE-024，但测试代码中只有一个 `test_upload_and_download_integrity` 独立函数且标注为 TC-FILE-023。

### 2. 关键代码

```python
# tests/api/4号/test_file_cases.py
DOWNLOAD_VERIFY_CASES = [c for c in FILE_CASES if c.get("tag") == "download_verify"]
# DOWNLOAD_VERIFY_CASES 未被任何参数化装饰器使用
```

### 3. 根因结论

TC-FILE-023 被合并到了独立函数 `test_upload_and_download_integrity`，而 TC-FILE-024 被遗漏，未创建对应的测试函数。

---

## 八、修复方案

### 推荐修复

方案一：为 TC-FILE-024 创建独立测试函数：

```python
def test_static_resource_url(auth_client, uploaded_file_info):
    """TC-FILE-024：验证上传文件的静态资源 URL 可访问"""
    file_id = uploaded_file_info["id"]
    resp = auth_client.request("GET", f"/v1/file/{file_id}/static")
    assert resp.status_code == 200
    # 验证返回的是文件内容而非 JSON 错误
    content_type = resp.headers.get("Content-Type", "")
    assert "json" not in content_type.lower()
```

方案二：将 `test_upload_and_download_integrity` 扩展为同时覆盖 TC-FILE-023 和 TC-FILE-024。

### 后续推荐
- 对所有 YAML 用例增加"是否被测试函数覆盖"的自动检查
- 在 CI 中增加 `pytest --collect-only` 结果与 YAML 用例数的对比步骤
