# Bug Report: 重复商品下单返回500

**Bug ID**: BUG-ORDER-VALIDATION-001  
**标题**: 同一订单包含重复商品ID时返回500内部错误  
**模块**: 订单系统 / 参数校验  
**严重级别**: 中高  
**优先级**: P1  
**状态**: 已定位 / 未修复  
**发现日期**: 2026-06-19  
**提交人**: 测试团队3号

---

## 一、问题概述

调用 `POST /v1/order` 时，如果 `products` 中包含两项相同的 `product_id`，参数校验层不会拒绝或合并重复商品。业务层继续创建两条具有相同联合主键的 `order_product` 记录，最终返回HTTP 500。

该问题使客户端无法获得明确的参数错误，也可能被利用来触发稳定的服务端异常。

---

## 二、影响范围

- 订单创建接口：`POST /v1/order`
- 重复商品与购物车合并场景
- 库存合计校验
- 统一异常处理

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地测试环境
- 服务地址：`http://127.0.0.1:5000`
- 数据库：MySQL 8.0.41 / `zerd`
- Python：3.11.15
- 测试账号：`user`（用户ID 31）
- 商品：ID 1，库存998

---

## 四、复现步骤

1. 使用账号 `user / 123456` 获取Token。
2. 以该Token调用 `POST /v1/order`。
3. 发送以下请求：

```json
{
  "products": [
    {"product_id": 1, "count": 600},
    {"product_id": 1, "count": 600}
  ]
}
```

4. 观察响应状态码和响应体。

---

## 五、实际结果

接口返回HTTP 500：

```json
{
  "error_code": 1007,
  "msg": "The server encountered an internal error and was unable to complete your request. Either the server is overloaded or there is an error in the application.",
  "request_url": "POST /v1/order"
}
```

测试清理后确认未残留有效订单，但接口错误类型不正确。

---

## 六、预期结果

系统应选择以下一种明确策略：

1. 在参数校验阶段发现重复商品并返回HTTP 400/422；或
2. 先按 `product_id` 合并数量，再以合计数量1200执行库存校验并返回库存不足。

不应返回500内部服务器错误。

---

## 七、根因分析

1. `OrderPlaceValidator.validate_products()` 只逐项检查ID和数量是否为正整数，没有检查重复商品。
2. `OrderService.__create_order()` 对原始列表逐项创建 `Order2Product`。
3. `order_product` 使用 `(order_id, product_id)` 联合主键，重复商品导致主键冲突。
4. `IntegrityError` 处理依赖 `e.orig.errmsg`，兼容性不足，最终未转换为明确业务错误。

---

## 八、修复建议

1. 在订单参数校验或Service层按 `product_id` 聚合数量。
2. 聚合后统一进行库存校验，防止分拆数量绕过库存规则。
3. 如果不允许重复商品，直接返回明确的400参数错误。
4. 修正 `IntegrityError` 处理逻辑，不依赖特定驱动才存在的 `errmsg` 属性。
5. 增加重复商品、重复主键和事务回滚回归测试。
