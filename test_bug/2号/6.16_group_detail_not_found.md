# Bug Report: 超级管理员组详情查询返回不存在

**Bug ID**: BUG-GROUP-DETAIL-001  
**标题**: GET `/cms/group/1` 查询超级管理员组时返回 404（"分组不存在"）  
**模块**: 权限组管理  
**严重级别**: 中  
**优先级**: P1  
**状态**: 已定位  
**发现日期**: 2026-06-16  
**提交人**: 测试团队 2号

---

## 一、问题概述

调用 `GET /cms/group/1` 查询超级管理员组详情时，接口返回 HTTP 404（`msg: "分组不存在"`）。而 `GET /cms/group/all` 查询所有权限组正常返回列表，说明 Groups 整体可查。问题仅出在按 ID 查询 `group_id=1`。

---

## 二、影响范围

### 受影响功能
- 权限组详情查询
- 权限组编辑页面（需要先加载详情）

### 受影响接口
- `GET /cms/group/{id}` — 仅 `id=1` 受影响

### 业务影响
- 无法查看超级管理员组的详细信息及其权限列表
- 权限组管理页面详情展示功能不可用

---

## 三、复现环境

- 项目：`mini-shop-server`
- 环境：本地开发环境
- 服务地址：`http://127.0.0.1:5000`
- 数据库：MySQL 8.4.9
- 测试数据：种子脚本插入 groups id=1（超级管理员组）
- 测试接口：`GET /cms/group/{id}`

---

## 四、复现步骤

### 步骤 1：获取管理员 Token
```bash
TOKEN=$(curl -s -X POST http://127.0.0.1:5000/v1/token \
  -H "Content-Type: application/json" \
  -d '{"account":"super","secret":"123456","type":100}' \
  | python -c "import sys,json; print(json.load(sys.stdin)['data']['token'])")
```

### 步骤 2：查询 group_id=1 详情
```bash
curl -s http://127.0.0.1:5000/cms/group/1 -u "$TOKEN:132"
```

### 步骤 3：对比查询 group_id=2 详情
```bash
curl -s http://127.0.0.1:5000/cms/group/2 -u "$TOKEN:132"
```

### 步骤 4：对比查询所有权限组
```bash
curl -s http://127.0.0.1:5000/cms/group/all -u "$TOKEN:132"
```

### 步骤 5：观察结果
group_id=1 返回 404；group_id=2 正常返回；/all 正常返回列表含 id=1。

## 六、预期结果

## 七、根因分析

### 1. 现象分析
- `/all` 列表正常返回 `id=1`，说明 `Group` 表中 id=1 的记录存在
- `id=2` 正常、`id=1` 报 "权限不足"，说明不是数据不存在，而是被**鉴权逻辑拦截**
- 接口使用 `@auth.admin_required` 装饰器，进入业务代码前先经过权限检查

### 2. 关键代码
- [app/api/cms/group.py:36-40](app/api/cms/group.py#L36-L40)：`get_group()` 使用 `@auth.admin_required`
- [app/core/token_auth.py](app/core/token_auth.py)：`admin_required` 装饰器逻辑
- 该装饰器可能对 id=1 做了特殊限制（如禁止查看超级管理员组）

### 3. 根因结论

**`get_group(1)` 中 `group.append('auth_list')` 触发了 `auth_list` property，该 property 查询 Auth 表获取 group_id=1 的权限记录后，调用 `get_ep_id(auth_name)` 查找权限名对应的 ID。** 种子数据在 Auth 表中插入了 name="查询所有权限组" 的记录，但该名称在 `EP_INFO_LIST`（由 `load_endpint_infos()` 从 `route_meta` 构建）中不存在，`get_ep_id()` 抛出 `NotFound(msg='权限名:查询所有权限组 不存在')` → error_code: 10100。

**关键代码定位**：
- `app/models/group.py:24-28`：`auth_list` property 调用 `get_ep_id(auth[0])`
- `app/core/auth.py:53-64`：`get_ep_id(name)` 遍历 EP_INFO_LIST，找不到则 `raise NotFound`
- `app/core/auth.py:77-95`：`load_endpint_infos()` 从 EP_META 构建 EP_INFO_LIST
- 种子数据 Auth 表：name="查询所有权限组" 不在 EP_META 中 → 触发 NotFound

## 八、修复方案

### 当前采取的修复策略
- **方案 1**：确认 `admin_required` 装饰器是否对 id=1 做了硬编码排除，若有则移除
- **方案 2**：若为权限映射问题，检查 auth 表与 group 表的关联关系

### 后续推荐优化方向
- 统一鉴权逻辑，避免对特定 ID 的特殊处理
