## 一、conftest.py 提供的资源

### 直接可调用的 fixture（import 即用）

| Fixture | 作用域 | 用途 |
|---------|--------|------|
| `base_url` | session | `http://127.0.0.1:5000`（由 tests/conftest.py 提供） |
| `timeout` | session | 请求超时 10s |
| `initialize_module` | module | 每个模块前后自动运行 `fake.py --scope all` 重置数据库 |
| `ensure_running` | module | 自动检测→启动 Flask 服务，保证测试期间服务在线 |
| `tokens` | module | 返回 `{super, admin, user}` 三个已登录 token |
| `all_tokens` | module | 比 tokens 多一个 `Allen3D` |
| `server_process` | module | 返回当前 Flask 进程的 PID |

### 从 conftest 导入的辅助函数

```python
from tests.system.conftest import (
    _fetchone,          # (sql, params) -> dict | None
    _fetchall,          # (sql, params) -> list[dict]
    _execute,           # (sql, params) -> int（执行 UPDATE/DELETE/INSERT）
    _find_all_flask_pids,  # -> list[int]  所有 server.py 进程 PID
    _find_pid_by_port,     # (port=5000) -> int | None  通过 netstat 查端口占用
    _force_free_port,      # (port, max_wait) -> bool  强杀+轮询释放端口
    _kill_all_flask,       # -> int  杀死所有 Flask 进程
    _start_server,         # (env_mode=None) -> Popen  启动 Flask 子进程
    _stop_server,          # (proc) 优雅终止
    _wait_until_ready,     # (base_url, timeout=30) -> bool  轮询等 /health
)
```

### pytest.ini 中已有的 markers

```ini
recovery: Recovery tests (kill/restart, DB reconnect, transaction rollback)
deployment: Deployment tests (env switch, API docs)
stability: Stability and compatibility tests (continuous requests, multi-role access)
slow: Long-running tests (30-min continuous requests)
perf: Performance tests (concurrent stress)
security: Security tests (injection, tampering, privilege escalation)
```

`slow` 和 `perf` 和 `security` 已经注册，可以直接用。

## 三、关键注意事项

### 1. 测试函数依赖 fixture 时**必须**同时声明 `initialize_module` 或 `ensure_running`

如果直接用 `tokens` fixture，它内部已依赖 `initialize_module` + `ensure_running`，不需要额外声明。

但如果测试函数不依赖 `tokens`（比如匿名请求的测试），必须声明 `ensure_running`：

```python
# ✅ 正确 — 依赖 tokens，服务会自动启动
def test_xxx(base_url, timeout, tokens):
    ...

# ✅ 正确 — 不依赖 tokens，手动声明 ensure_running
def test_xxx(base_url, timeout, ensure_running):
    ...

# ❌ 错误 — 只测匿名请求，但没声明 ensure_running，服务可能没启动
def test_xxx(base_url, timeout):
    ...
```

### 2. 不要乱用 `_force_free_port()` 和 `_kill_all_flask()`

**性能测试不需要 kill Flask**，直接对运行中的服务发请求即可。只有恢复测试（S-09）才需要 kill 重启。

如果压测并发过高把服务搞挂了，用 `_wait_until_ready()` 等它恢复。

### 3. 性能测试注意并发限流

用 `concurrent.futures.ThreadPoolExecutor` 或 `pytest-xdist`。服务是单进程 Flask dev server，200 并发已经接近极限，超了会导致 ConnectionError——这是正常现象，记录到报告中即可。

### 4. 安全测试的越权场景

admin 账号（auth=1, group_id=1）在种子数据中存在，但：
- **不能过 `admin_required`**（要求 auth=2，只有 super 满足）
- **不能过 `group_required`**（admin 的 group=1 不是管理员组）
- S-07（CMS 未授权访问）：用 user token 测 `@auth.admin_required` 接口时预期 401

### 5. 测试函数内不要启动/停止 Flask

除非测试场景需要（如 S-12 环境切换），否则让 `ensure_running` 自动管理。你自己 `_start_server` 会和已有进程抢端口，引出一堆问题。

### 6. 需要并发工具可以共用 psutil

conftest.py 已经 import 了 `psutil`，你的性能测试如果需要看 CPU/内存可以直接用。

### 7. 测试隔离问题

如果压测导致数据库数据变化（比如 S-03 超卖验证），利用 `initialize_module` 的 teardown 在每个模块结束后自动重置。如果需要在单个测试内重置，自己调 `fake.py --scope all`：

```python
import subprocess, sys
subprocess.run([sys.executable, "fake.py", "--scope", "all"], check=True)
```
