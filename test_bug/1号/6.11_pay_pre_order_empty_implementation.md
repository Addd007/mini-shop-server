# Bug Report: 预支付接口微信预订单逻辑为空实现导致服务器端异常

**Bug ID**: BUG-PAY-PREORDER-001  
**标题**: `POST /v1/pay/pre_order` 通过订单校验后进入未实现的微信预支付逻辑并返回服务器端异常  
**模块**: 订单系统 / 支付 / 微信预支付  
**严重级别**: 高  
**优先级**: P0  
**状态**: 已定位  
**发现日期**: 2026-06-11  
**提交人**: 测试团队 1号

---

## 一、问题概述

调用预支付接口 `POST /v1/pay/pre_order` 时，当订单存在、订单属于当前用户、订单状态为未支付且库存校验通过后，接口会进入微信预支付逻辑。但当前微信预支付逻辑尚未实现，代码中使用了空变量和占位逻辑，最终导致服务器端异常。

该问题会导致用户无法获取微信支付预订单信息，支付流程无法继续执行，直接阻断订单支付链路。

---

### 受影响功能

- 微信支付参数生成
- 支付签名生成

### 受影响接口 / 页面
- `POST /v1/pay/pre_order`

- 用户无法完成支付
- 订单只能创建，不能进入支付流程
- 支付回调、支付重通知、并发支付等后续用例无法完整验证
- 核心交易闭环被阻断

```json

  "msg": "成功",
```

如果本地环境未配置微信支付参数，也应返回明确的业务错误，例如：


## 七、根因分析

### 1. 现象分析

该问题不是订单不存在、订单用户不匹配或订单状态错误导致的，因为这些校验已在 `__check_order_valid()` 中完成。

当订单校验和库存校验通过后，程序进入 `__make_wx_pre_order()` 和 `__get_pay_signature()`，随后触发未处理异常。

### 2. 关键代码 / 关键逻辑

预支付主流程：

```python
def pay(self):
    self.__check_order_valid()
    status = OrderService().check_order_stock(self.order_id)
    if not status['pass']:
        return status
    return self.__make_wx_pre_order(status['order_price'])
```

微信预支付方法当前为空实现：

```python
def __make_wx_pre_order(self, order_price):
    user = User.query.filter_by(id=g.user.id).first_or_404()
    openid = user.openid
    if not openid:
        # openid不存在
        pass
    wx_order_data = None
    return self.__get_pay_signature(wx_order_data)
```

签名方法同样为空实现，并且会访问 `None`：

```python
def __get_pay_signature(self, wx_order_data):
    '''签名'''
    wx_order = None
    if wx_order['return_code'] != 'SUCCESS' or wx_order['result_code'] != 'SUCCESS':
        pass  # 记录到日志里
    return None
```

其中：

```python
wx_order = None
wx_order['return_code']
```

会触发：

```text
TypeError: 'NoneType' object is not subscriptable
```

此外，`user.openid` 也存在数据模型不匹配风险。当前项目中微信 openid 已通过 `identity` 表维护，`User` 模型并没有真实的 `openid` 字段，因此这里也无法可靠获取支付所需 openid。

### 3. 根因结论

问题根因是预支付接口的微信统一下单与签名生成逻辑尚未实现，但接口已暴露并进入可调用状态。代码中存在 `pass`、`None` 占位和对 `None` 的下标访问，导致合法预支付请求最终返回服务器端异常。

---

## 八、修复方案

### 当前采取的修复策略
- 当前已完成问题定位，尚未实现微信预支付逻辑。
- 测试侧应将 `TC-ORDER-004` 标记为阻塞或失败，原因是预支付核心逻辑未实现。

### 后续推荐优化方向
- 实现微信统一下单接口调用逻辑。
- 从 `Identity` 表中按 `ClientTypeEnum.WX_MINA` 获取当前用户的 openid。
- 校验微信支付配置是否完整，例如 appid、mch_id、api_key、notify_url 等。
- 对微信统一下单失败场景返回明确业务错误。
- 实现 `__get_pay_signature()`，返回前端调起微信支付所需参数。
- 如果当前环境不支持真实微信支付，应提供 mock 支付模式，方便测试环境验证订单支付链路。

## 九、修复结果

当前状态：已定位，待修复。

修复完成后，应验证以下场景：

- 未支付订单可成功生成预支付信息。
- 订单不存在返回明确订单不存在错误。
- 订单不属于当前用户返回权限错误。
- 已支付订单返回订单已支付错误。
- 库存不足时返回库存不足状态。
- 微信支付配置缺失时返回明确配置错误，而不是服务器异常。

## 十、建议

1. 将预支付逻辑从订单校验逻辑中拆分，分别测试订单校验、库存校验、微信统一下单、签名生成。  
2. 为本地测试环境提供 mock 微信支付实现，避免真实第三方依赖阻塞接口测试。  
3. 对所有 `pass` 和 `None` 占位逻辑进行排查，避免未实现代码进入生产接口路径。  
4. 明确 `POST /v1/pay/pre_order` 的返回结构和错误码规范。  
5. 在接口文档中说明前置条件：订单必须未支付、属于当前用户、用户必须具备微信 openid。

## 十五、结论

该问题属于支付模块核心逻辑未实现导致的高优先级缺陷，已定位到 `PayService.__make_wx_pre_order()` 和 `PayService.__get_pay_signature()` 中的占位逻辑。当前接口无法返回任何可用的微信预支付参数，导致支付链路被阻断。建议按 P0 优先级实现或提供测试环境 mock 支付能力。
