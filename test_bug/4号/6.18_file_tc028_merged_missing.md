# Bug Report: TC-FILE-028 无独立测试函数，文件移动测试被合并导致覆盖缺失

**Bug ID**: BUG-FILE-COVERAGE-028  
**标题**: YAML 中 TC-FILE-028（移动文件到根目录）属于 `file_move` 标签，但 `test_upload_to_folder_and_move` 函数将 TC-FILE-027 和 TC-FILE-028 合并为 1 个测试项  
**模块**: 文件管理 / 测试覆盖  
**严重级别**: 中  
**优先级**: P2  
**状态**: 已定位  
**发现日期**: 2026-06-18  
**提交人**: 测试团队 4号

---

## 一、问题概述

4号文件测试的 YAML 用例定义了 29 个用例，但 pytest 收集到的测试项只有 27 个（file 模块少了 2 个）。TC-FILE-028（移动文件到根目录）在 YAML 中定义为独立的 `file_move` 标签用例，但 Python 测试代码中 `test_upload_to_folder_and_move` 函数将 TC-FILE-027 和 TC-FILE-028 合并为 1 个测试项，导致 TC-FILE-028 未被作为独立测试收集和执行。

---

## 二、影响范围

### 受影响功能
- 文件移动到根目录
- 文件移动边界场景

### 受影响接口
- `PUT /v1/file/{id}/move`（文件移动）

### 业务影响
- TC-FILE-028 的独立验证目标（移动到根目录）未被单独覆盖
- 如果移动到文件夹和移动到根目录存在行为差异，无法被独立发现
- 两个场景合并在一个测试函数中，一个场景失败会导致另一个场景不被测试

## 七、根因分析

### 1. 现象分析

`FILE_MOVE_CASES` 列表被加载但未被任何参数化装饰器使用，`test_upload_to_folder_and_move` 是独立函数，内部串行执行了两个操作。

### 2. 关键代码

```python
# tests/api/4号/test_file_cases.py
FILE_MOVE_CASES = [c for c in FILE_CASES if c.get("tag") == "file_move"]
# FILE_MOVE_CASES 未被参数化使用

def test_upload_to_folder_and_move(auth_client, uploaded_file_info):
    """TC-FILE-027/028"""
    # 函数内部执行两个操作，但只算 1 个测试项
```

### 3. 根因结论

TC-FILE-027 和 TC-FILE-028 被手工合并为 1 个测试函数，且未使用参数化，导致 pytest 收集到的测试项少于 YAML 定义的用例数。

---

## 八、修复方案

### 推荐修复

方案一：使用参数化拆分为两个独立测试项：

```python
@pytest.mark.parametrize("case", FILE_MOVE_CASES, ids=[c["id"] for c in FILE_MOVE_CASES])
def test_file_move(auth_client, uploaded_file_info, uploaded_folder_info, case):
    file_id = uploaded_file_info["id"]
    path = case["params"]["path"].replace("{uploaded_file_id}", str(file_id))
    target = case["params"]["json"]["target_folder_id"]
    if target == "{uploaded_folder_id}":
        target = uploaded_folder_info["id"]
    resp = auth_client.request(case["params"]["method"], path, json={"target_folder_id": target})
    assert resp.status_code == case["expected"]["status_code"]
```

方案二：拆分为两个独立函数 `test_move_to_folder` 和 `test_move_to_root`。

### 后续推荐
- 排查其他测试函数中是否存在类似的"手工合并多个 YAML 用例"的情况
- 建立 YAML 用例数与 pytest 收集数的自动对比机制

## 十、建议

1. 将 TC-FILE-027 和 TC-FILE-028 拆分为独立的测试项
2. 建立"每个 YAML 用例对应一个测试项"的规范
3. 在 CI 中增加 YAML 用例数与 pytest `--collect-only` 结果的对比检查
4. 对于确实需要合并的场景，在 YAML 中使用 `depends_on` 或 `merge_with` 字段显式标注

## 十三、结论

该问题属于测试覆盖缺失，TC-FILE-028 被合并到 `test_upload_to_folder_and_move` 函数中导致未作为独立测试项收集。这是导致 4号 68 个 YAML 用例仅收集到 66 个测试项的原因之一（另一个缺失的是 TC-FILE-024）。建议拆分为独立测试项以完善覆盖率。
